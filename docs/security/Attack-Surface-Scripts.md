# Attack surface: scripts, templates and parsers

This file covers the code that runs inside the server as script: the JavaScript engine and what a script can call, the places where text that is not a source file is evaluated as an expression, a template or a script, how output is escaped when a screen renders, and the parsers that read bytes from outside (XML, zip, tar, images, spreadsheets). This is one file of the attack surface map. The index, how to read a row, the defaults and the lock-down advice are in [Attack-Surface.md](Attack-Surface.md).

## What a script can reach

### The engine and its limits

- Server scripts run on quickjs-oxide, pinned by git revision in the workspace `Cargo.toml` with `default-features = false`. The binding is `crates/moqui-core/src/script/` (`oxide/` for the engine, `host/` for the functions a script calls).
- Each thread that runs scripts has one runtime. Its heap cap is 64 MiB (`HEAP_CAP` in `crates/moqui-core/src/script/oxide/engine.rs`).
- Script runs nested on one thread are counted. The limit is 64 (`MAX_SCRIPT_DEPTH` in `crates/moqui-core/src/script/run.rs`).
- A script ends when the thread's deadline passes or the thread's interrupt flag is set (`thread_interrupted` in `run.rs`). The limit is computed by `script_limit_for` in `run.rs`: `resource-facade@script-timeout` seconds when it is a number, on every thread; else, on a request worker, the webapp's `webapp-list/webapp[webroot]/web-protection/requests@request-timeout` (300 seconds by default); else none. `script-timeout` is empty by default, so a script on a service, job or scheduler thread has no time limit unless a transaction's deadline gives one. Only `request_pool.rs` marks a thread a request worker, and the limit is armed only when no deadline is set.
- `eval` and the `Function` constructor are present in the server runtime: nothing removes them, and `FREEZE_HOST_GLOBALS_JS` (`oxide/engine.rs`) guards the host globals, not the built-ins. A server script has `ec` already, so they add nothing. No module loader is installed (`set_module_loader` has no caller under `crates/`), so `import` and `import()` load nothing, and the engine is built with no native module; `ec.resource.script(location)` is the one way to load code by location.
- A script's `RegExp` runs on quickjs-oxide's own backtracking engine (its `regexp` crate, a port of QuickJS's `libregexp`), which has no step limit of its own and polls the interrupt every 10,000 steps: a hostile pattern runs until the thread's deadline or the locked render's, and without end on a thread that has none.
- No code runs the promise job queue: `run_jobs` and `run_pending_job` have no caller under `crates/` outside a test, in the server runtime or the locked sandbox, so a job a script queues (`Promise.resolve(v).then(...)`) is never run and stays queued.
- A thread can be restricted to a list of host functions (`restrict_host_calls` in `crates/moqui-core/src/script/runtime.rs`). The engine binder checks it on each host call (`host_call_allowed` in `oxide/bind.rs`). The one caller is the load runner's user threads (`crates/moqui-host/src/test_client/mod.rs`). No other script class uses it.

### Classes of script

| Class | Where it runs | What it can call | Limits |
|---|---|---|---|
| Server script: a service script, XML actions, a screen's actions and transitions, a widget attribute expression, any text passed to `ec.resource.expression`, `condition`, `expand`, `expandNoL10n` or `script`, and a trusted template (`fancy`, `html.fancy`, `md.fancy`, `markdown.fancy`), which also has `sri` | The thread's runtime, with the caller's context | The whole host table: every `ec.*` member listed below, and the globals such as `System` and `StringUtilities` | 64 MiB heap, depth 64, the thread's deadline |
| Locked template: the `fancy-locked` and `html.fancy-locked` template extensions (`MoquiDefaultConf.xml` `template-renderer`), and a Shop theme package (`crates/moqui-core/src/script/theme/`, through `template::render_locked_bounded`) | A separate runtime for each thread and heap cap (`crates/moqui-core/src/script/oxide/templates.rs`), kept across renders. Its global object and everything reachable from it are frozen once at start, and each compiled template is a strict, frozen function that reads only the names its body uses, from the snapshot of the map passed in (`template.rs`) | The engine's built-ins, frozen (`Function` and indirect `eval` among them; code made with them runs in the same runtime and sees no snapshot name); three host functions, `format(value, pattern)`, `localize(text)` and `t(key)`; `$scope`, the snapshot reader; and each template's `raw`, `html`, `cssString` and prelude helpers. `localize` reads `LocalizedMessage` rows with authorization off and fills the shared `l10n.message` cache (`l10n.rs`). No `ec`, `sri`, context stack, module loader, file or network function; a host object in the snapshot becomes `null` | `LOCKED_TIME_LIMIT` 5 seconds and `LOCKED_MEMORY_LIMIT` 32 MiB in `crates/moqui-core/src/script/template.rs`, which a caller can only lower (a lower memory limit runs in a smaller sandbox); a theme page also has its own `Limits` (sections, blocks, depth, include depth, bytes) |
| Standalone runtime: `Standalone::start` in `crates/moqui-core/src/script/standalone.rs` | A runtime of its own. `start` installs no host function: the host object implements only `interrupt` | Nothing of the server | The caller's heap cap and deadline. The OpenUI check uses 64 MiB and 5 seconds (`crates/moqui-llm/src/ui/openui.rs`). The Vue SFC compile check uses 16 MiB and 2 seconds (`crates/moqui-llm/src/ui/vue_sfc.rs`) |
| Load runner user script | A thread under `restrict_host_calls` | Only the host functions the harness allows; a service the harness calls runs unrestricted (`HostCallsLifted`) | As a server script |
| Decimal expression: `crates/moqui-lib/src/decimal_expr.rs`, through `org.moqui.impl.ExpressionServices.validate#DecimalExpression` and `evaluate#DecimalExpression` (`crates/moqui-core/src/service/expressions.rs`), which read only their parameters and convert only the inputs the expression names. The report engine does not use it | No script engine. The module imports `rust_decimal` and the decimal helpers of `moqui_lib::object` only | Numbers, named inputs, operators and `if`, `min`, `max`, `abs`, `round`, `floor`, `ceil` | 2000 characters (`MAX_LENGTH`) and 32 levels of nesting; overflow and division by zero are errors |

The template renderers by file extension are in `MoquiDefaultConf.xml`: `fancy` (no escaping) and `html.fancy` (`${}` HTML escaped) are the trusted renderer, which runs on the script runtime with the live context, `ec` and `sri`, so a trusted template is a server script; `fancy-locked` and `html.fancy-locked` are the locked renderer; `md` and `markdown` are Markdown; `md.fancy` and `markdown.fancy` are Markdown through the trusted renderer; `html` is not a template. A location's renderer is chosen by its file name alone, the longest registered extension the name ends with (`renderer_for` in `script/template.rs`), whatever the scheme: `http`, `https` and `dbresource` locations are rendered the same way, so whoever controls the end of a location's name chooses the trusted or the locked renderer. A location whose extension has no renderer (`html`, or any other) is returned as its text, and a `<text template="true">` widget writes it unescaped. Locations are rendered by name from `ec.resource.template(location, data)` (`script/host/globals.rs`), `sri.renderText` and `sri.renderTextValue` (a screen's `<text>` widget, `screen/sri/sections.rs`), a child file of an `include-child-content` screen, and a screen's `screenDoc` transition (`screen/saved_finds.rs`). A `.fancy` or `.fancy-locked` file under a screen is never sent as a static file (`screen/static_files.rs`). Since SEC-SCR-81 a screen's templated `<text>` (and `sri.renderText`/`renderTextValue` with a template) renders only a component's own file: a `component://` location, or a path under the runtime's components, a component's directory or the rendering screen's own directory, never one with `..` or another scheme (`dbresource://`, `file:`, `git://`, `runtime://`); any other is logged and renders nothing (`template_location_allowed`, `screen/sri/sections.rs`), so a request-named `templateLocation` or `pageLocation` cannot run a planted file. `ec.resource.template` is not limited this way; a wiki page renders through `WikiServices.render#WikiPage`.

### Host members by capability

A server script has all of these. None of them checks a permission of its own unless the row says so. Authorization of an entity operation or a service call is the artifact authorization of the execution context ([Attack-Surface-Data.md](Attack-Surface-Data.md#entity-authorization-and-row-filters)).

Other crates add paths with `host::register` before the first script runs.

### The effect fence

- The fence is a thread-local stack in `crates/moqui-entity/src/entity/fence.rs`. Its frames are a read fence, a lifted stretch, a sim preview and a permit for one remote origin.
- `ALLOWED_ENTITIES` lists the entities a thread under the read fence may write: sequence, authorization failure, tarpit, login history, visit, visitor, session, and the agent run and model call records.
- The effects are `AsyncCall`, `RemoteCall`, `Print`, `Mail`, `Sql`, `Resource`, `Notify` and `Process`. Each is checked where the effect happens, with `fence::check_effect`: in `script/host/tools.rs` (process, HTTP), `context/resource.rs` (resource writes), `outbound.rs`, `notify/message.rs`, `service/call.rs`, `sftp.rs`, `service/backup.rs`, `service/backup_store.rs`, `service/web_push.rs`, `service/chat_link.rs`, `service/system_sync/`, and in `moqui-mail`, `moqui-git`, `moqui-devkit` and `moqui-llm`.
- The fence is entered only at these places: a screen render whose `fenced` flag is set and the preview of proposed screen text (`crates/moqui-core/src/screen/render.rs` lines 293 and 764); an agent tool run (`crates/moqui-llm/src/run/step.rs`, `tools/lazy.rs`); the agent's facts, prompts and constitution providers (`facts.rs`, `assist/prompts.rs`, `constitution/resolve.rs`); an approval preview as a sim fence (`approval/steps.rs`, `approval/preview.rs`); a remote MCP tool as a permit (`tools/mcp_client.rs`).
- A script that runs for a web request, a REST call, a job or a service call outside those places is not fenced. The fence belongs to the thread: work handed to another thread is not fenced.

## Who can author code that runs

Every row is a place where text that is not a source file of a component is evaluated on the script runtime as a server script, with everything in [Host members by capability](#host-members-by-capability). Where the text is a record, whoever may write that record authors code.

### From screen XML

The screen templates (`runtime/components/base/framework/template/screen/ScreenHtml.js`, `ScreenQvt.js`, `ScreenTui.js`) evaluate widget attributes with `ec.resource.expression` and `ec.resource.condition` (`text-map`, `condition`, `hide`, `from`, `cid-map`, a currency unit) and expand `${}` in attribute text with `ec.resource.expandNoL10n`. The input is the attribute text of the screen definition, not the value it produces: a value that an expression returns is not expanded again.

### Reports, alerts, dashboards and spreadsheet formulas

The report engine (`crates/moqui-report`) evaluates no author text as script. A `calculate` step is one of `+ - * /` between two fields or a field and a number (`frame.rs`); reduce, group and footer calculations are names from a fixed list; a filter step compares, or matches a regular expression of the linear `regex` crate within a 1 MiB size limit. A dashboard variable `$name` or `${name}` is replaced by its value when the whole string is the reference (`lib.rs`), and is not evaluated. An alert condition is four numeric comparisons (`alert.rs`). Titles are looked up as localized messages, not expanded, and a notification title that holds `$` is passed by name. The two places where the engine evaluates text are a document definition's title template and link fields ([From a record](#from-a-record)) and the email template's own subject.

A spreadsheet formula, in a CalcGrid document (`crates/moqui-calc`) or in `org.moqui.resource.SpreadsheetServices.calculate#Spreadsheet` (`crates/moqui-core/src/service/spreadsheet_calc.rs`), runs in the IronCalc engine (`ironcalc_base`) and reaches the cells of its own workbook, the data sheets of the room it is evaluated in included. The engine has no code that reads a file, opens a connection, runs a process or calls a service; one function reads the host, `INFO("system")` (the operating system's name), and `NOW`, `TODAY` and `RAND` read the clock and a generator. Recursion is bounded (64 levels and 256 KiB of stack, then an unwind and replay) and circular references are found; there is no time limit and no limit on the cells a formula reads, and an evaluation runs under the room's lock. An author's formulas go into an exported `.xlsx` as formulas (`crates/moqui-core/src/workbook.rs`). `calculate#Spreadsheet` reads any resource `location` and writes the calculated workbook to any `outputLocation`, with no check of either and at most 100,000 cells a range; no screen, REST resource or other service calls it, so it is reached through Tools › Service Run or a script.

### Model output and themes

- The OpenUI parser and the Vue SFC compile check run a library's code over model output in a standalone runtime, which has no `ec` and no host function. See [Attack-Surface-AI.md](Attack-Surface-AI.md).
- A Shop theme package renders in the locked renderer. The only caller of `template::render_locked_bounded` outside the template module is `crates/moqui-core/src/script/theme/compose.rs`.
- The locked renderer is also reached for every `.fancy-locked` location, through `ec.resource.template`: mr-mantle's message templates (`mantle/party/MessageTemplates.js`, files of fixed names such as `body.html.fancy-locked`), the stored quote texts (`mantle/order/SalesQuoteIssues.js`) and the request-for-quote acknowledgement (`SalesQuoteRequests.js`). The last two take the location from a `SalesPolicy` field, for which `store#SalesPolicy` declares no parameter (`SalesApprovalServices.xml`). A wiki page of type `fancy-locked` is the other case ([From a record](#from-a-record)).
- `ec.resource.theme` takes a theme package as a JSON object of file texts from the calling service (`theme/package.rs`): the framework unpacks no archive and writes no file for a theme, and binary assets are named by digest. A package path must fit the fixed layout, with no absolute path and no `\`, `.` or `..` part; at most 2000 files, 1 MiB a text file and 1 MiB an assembled template; snippet recursion is refused. Layout, section, block and snippet names are looked up in the package's map, never as a location. A theme's limits only tighten the operator's (`theme/mod.rs` `lowered_by`).
- A theme template's source, its snippets and each render's output are checked at every render (`theme/compose.rs`): tokenized as HTML and refused for `script`, frames, `form`, `base`, `math`, SVG `foreignObject` and animation, any `on*` attribute, `srcdoc`, `formaction`, `http-equiv`, a `javascript:` or non-image `data:` URL and a load from an origin not approved (`theme/markup.rs`). `meta` is allowed with any `name`, and a link may go to any `http` or `https` site. Each expression is checked by `theme/expr.rs` (no `new`, no function body, a list of denied names), which its comment calls secondary to the lock; a theme expression can still reach `Function` through a property name built at run time. A fragment placeholder is taken only in text, with the page's random nonce, and only when the render's own view held it. Rich text reaches a page only through `safe_html::clean`, and the SVG cleaner (`theme/svg.rs`) writes only allow-listed elements and attributes. Setting values hold no expression and are typed (a colour is hex only).
- A CSS or SVG asset and the manifest's `styles` are checked only by `validate` (`theme/package.rs`), not at a render, so they hold only when the caller validates before it serves; mr-mantle validates at publish and restore (`mantle/public/Themes.js`). CSS is checked by `check_css` for `url()` and `@import` on the text `decode_css` gives, which has comments removed and `\` escapes decoded over the whole text, strings included.

## Rendering and escaping

- `ScreenHtml.js` (the html render mode) has an escape helper `e`. The outputs read in this pass use it except as listed below.
- The display, label and link text outputs are escaped unless the widget's `encode` attribute is `false`; with `encode="false"` the value is written as it is (`ScreenHtml.js` lines 612 to 737, and the generated form-list code at line 2329).
- An `editable` widget's text is HTML encoded, in the html, qvt and server-static qvt templates (`$mq.enc`), unless the screen sets `encode="false"`, as a label's is (SEC-SCR-08, fixed: it was written as it is unless `encode="true"`, and mr-marble's TaskSummary showed a task's name and description that way).
- The HTML view widget cleans its `html` attribute with `StringUtilities.cleanHtml` and escapes its `text` attribute (`ScreenHtml.js` near line 1810).
- The sanitizer is `moqui_lib::safe_html::clean` (`crates/moqui-lib/src/safe_html.rs`): ammonia 4 with its default allow-list, plus `data-mention-id`, `data-record-entity` and `data-record-id` on a `span`; the chat cleaner (`clean_chat`) also drops any image whose `src` is not `/richTextImage/<id>`. Its callers are the service parameter check, `StringUtilities.cleanHtml`, the theme adapter's `sanitize_rich_text` (`crates/moqui-core/src/script/theme/markup.rs`) and the desktop client's offline compose (`crates/moqui-client/src/offline.rs`).
- HTML is checked on input by the service parameter rule (`crates/moqui-core/src/service/validate.rs` `clean_html`): text with a `<` is an error unless the parameter has `allow-html`. With `allow-html="safe"` the text is cleaned by the sanitizer. With `allow-html="any"` it is kept as it came. A list parameter's string items are checked the same way. A value that does not pass through a service parameter is not checked.
- Markdown is converted by `moqui_lib::markdown::to_html` with pulldown-cmark 0.13 and its `html` feature, tables on. Raw HTML blocks and inline HTML are written as they are, `<script>` included, and a link or image destination as given, so `javascript:` and `data:` stay; no `rel` or `target` is added, and the output is not sanitized. `ec.resource.markdownHtml` is that function; its callers in mr-mantle (`Smithy.js`, `SmithySite.js`, `ForumImport.js`, `SitePages.js`, and `ForumCore.js` in `renderSource`) clean the result with `StringUtilities.cleanHtml`. The `md` and `markdown` template renderers are the same function and do not clean.
- In the tui render mode HTML becomes text through `crates/moqui-core/src/screen/html_text.rs`, which only tokenizes (html5ever), skips the content of `script`, `style`, `iframe`, `noscript`, `template`, `head` and `title`, and strips control characters from text and URLs. A link's URL goes to the client's link list unless it starts with `#` or `javascript:`, compared as written.

### Spreadsheet output

- The xlsx render mode (`crates/moqui-core/src/screen/xlsx.rs`) and the workbook writer (`crates/moqui-core/src/workbook.rs`) write a text as a shared string, never through the formula parser, and clean a sheet name. A CalcGrid data sheet's record values are text too (`moqui-calc/src/fill.rs`).
- The csv render mode (`ScreenCsv.js` `$csv`) puts `'` before a value, headers included, that starts with `=`, `+`, `-`, `@`, a tab or a CR unless it is a plain number, and quotes a value with a comma, a quote or a line break. It does this for each widget's text on its own, and a cell is the texts of the field's widgets one after another (the xlsx mode joins them first). A report widget in a csv render goes through the report's CSV.
- The report engine's CSV (`moqui-report/src/schedule.rs` `csv_cell`) quotes every cell, doubles quotes and puts `'` before a text that starts, after white space, with one of those characters. The BOSS report exports (`ironstone/commerce/Reporting.js`, `purchasing/Reports.js`, `customerservice/Reporting.js`) do the same for every cell, titles and column heads included, but a plain number in a number column.
- The Tools data grid's CSV export (`moqui-tools/src/grid.rs`), the entity CSV writer (`moqui-entity/src/entity/query_rest.rs`) and an ETL import's error file (`moqui-tools/src/etl/transform.rs`) quote for CSV and nothing else, so a value that starts with `=` is a formula in the file. The entity writer is a data format: its file loads back unchanged.

### PDF through Chromium

- PDF output starts a headless Chromium (`crates/moqui-host/src/pdf.rs`, `crates/moqui-host/src/chromium.rs`). The binary is found at startup; without one PDF is not available.
- The launch arguments are `--headless=new`, `--remote-debugging-pipe` (on Windows `--remote-debugging-address=127.0.0.1` and `--remote-debugging-port=0`), `--no-first-run`, `--no-default-browser-check`, `--disable-gpu`, `--disable-extensions`, `--disable-background-networking`, `--disable-component-update`, `--disable-sync`, `--metrics-recording-only`, `--password-store=basic`, `--use-mock-keychain`, then `--proxy-server=127.0.0.1:9`, `--proxy-bypass-list=<-loopback>`, `--force-webrtc-ip-handling-policy=disable_non_proxied_udp` and a `--user-data-dir` under the runtime's `tmp` directory. `--no-sandbox` is not among them.
- On Unix DevTools is the pipe on the browser's descriptors 3 and 4, NUL-delimited JSON (`pdf/cdp.rs` `Connection::over_pipe`): no socket (SEC-SCR-10). On Windows it is a random port on 127.0.0.1, read from `DevToolsActivePort` in the profile directory.
- A page opens at `about:blank`. Every request the page makes that pauses in the `Fetch` domain is failed with `BlockedByClient`. The proxy arguments send every other connection, loopback included, to 127.0.0.1 port 9.
- One document has 60 seconds by default (`screen-facade` `pdf` `timeout`). A PDF preview is at most 25 MiB.
