# Attack surface: mail

Inbound and outbound mail. This is one file of the attack surface map. The index, how to read a row, the defaults and the lock-down advice are in [Attack-Surface.md](Attack-Surface.md).

## Mail

There is no open SMTP receiver by default. `smtp_listen_port` empty does not start one. The host default is `127.0.0.1`. There is no default port (the doc example is 2525). Only internet mode (`smtp_internet=true`, or `internet="true"` on the `smtp-server`, which MoquiEdgeConf.xml sets) takes mail from anyone, on port 25 of an edge node; see [Edge node](Attack-Surface-Cluster-Edge.md#edge-node) below. `inbound-smtp` is an Enterprise and Maximal feature. Dev and Lite omit it. If the port is set on a build without the feature, startup logs an error and does not listen.

The listener is the last hop behind an operator-run gateway (`docs/interfaces/Mail-Inbound.md`). There is no SMTP `AUTH` and no client certificate. The allow-list is the gateway. A peer outside `smtp_allowed_addresses` gets `554` at connect and the connection closes. An empty allow-list refuses to start the listener. `proxy-protocol`, `starttls`, and `require-tls` default to false. STARTTLS with no certificate does not start the listener. `dsn` defaults to false. The message cap is 25 MiB (`max-message-size` 26214400), 100 recipients, 20 connections. In internet mode an empty allow-list takes mail from any address, and a non-empty one still refuses every other address with `554`. In internet mode STARTTLS is on by default, each address is limited (`max-connections-per-ip` 5, `connections-per-minute` 30; IPv6 by its /64), and SPF, DKIM, DMARC and ARC are checked after the data within 45 seconds, with the listener's own `Authentication-Results` written and any claiming its authserv-id removed; a DMARC reject policy is refused (550). Rspamd's verdict, when `mail_rspamd_url` is set, fails open ([Mail-Inbound](../interfaces/Mail-Inbound.md)).

A permitted gateway can `RCPT TO` a hosted (`EakHosted`) or shared (`EakShared`) address that has no incoming IMAP or POP server. Other recipients are `550`. After `DATA`, the message is stored in that account's Inbox, or Junk when a configured spam header starts with yes or true. That store runs with authorization disabled, including the app `EmailMessage` ECA when Mantle is loaded. `RCPT TO` takes no address of another domain, so nothing is relayed. A stored message can still make the server send mail: the "delivered" notice, an out-of-office reply and a rule's forward (the paragraph on mail sent because a message arrived, below). `VRFY` answers `252`. Empty `smtp_authserv_id` keeps every `Authentication-Results` header, including a forged one; it warns at startup on a node whose listener takes mail from a gateway, on a local node paired with an edge node and on a node that syncs mail by IMAP or POP3, not on an edge node in internet mode, whose listener's own fields are under `smtp_hostname` then. A reverse path with a quoted local part (`"a; dmarc=pass header.from=bank.example"@evil.example`, valid SMTP) cannot add results to the listener's own field: its `smtp.mailfrom` is written as the domain alone (RFC 8601 allows it), and the delivery's reading of trusted fields splits them on `;` outside quoted strings and comments only. Out of internet mode the listener does not check SPF, DKIM, or DMARC; the gateway does.

Only a mail administrator makes an account the listener delivers to. The MailAccounts wizard (`BasicComms/Settings/MailAccounts/Add`) offers every user of the app a "Hosted here" account and a "Shared, delivered here" account at an address the user types. `org.moqui.comms.MailSettingsServices` saves it with `gatewayDelivery` through `create#EmailAccount` with kind `EakHosted` or `EakShared`, no server and status `EasPaused`. `create#EmailAccount` refuses a hosted or shared account with no incoming server, and `update#EmailAccount` refuses to give such an account another address or to make an account one, unless the caller has the permission `EMAIL_ACCOUNT_HOSTED` (granted to `ADMIN`) or authorization is disabled (plans/Security-Review.md SEC-MAIL-01, fixed); the wizard shows the refusal. The domain of the address is not checked. A recipient of the listener is an account of kind `EakHosted` or `EakShared` that is not `EasRemoved` (a paused one counts) and has no incoming server, matched on `EmailAccount.emailAddress` and then `EmailIdentity.emailAddress` without regard to case, then again without the plus tag (`crates/moqui-mail/src/delivery.rs`). When several accounts have the address, the one with the lowest id gets the mail.

Listener limits. A command line is at most 4096 bytes (`500`, then the connection closes). Twenty commands answered with a syntax or sequence error close the connection (`421`); an unknown recipient (`550`) is not counted. `command-timeout` is 300 seconds for each line or data chunk and `session-timeout` 1800 seconds for a connection. A session has no limit on the number of messages or of refused recipients. A message over `max-message-size` is read to its end, not kept, and answered `552`. A message whose `Message-ID` the account already has with a `receivedDate` is answered as stored and not stored again, whatever its sender or content. A message with no header fields is `554`. Each message is held in memory once per connection (at most `max-connections` times `max-message-size`). In internet mode with `mail_rspamd_url` set the whole message is posted to `{url}/checkv2` with the client address, EHLO name, envelope sender and recipients as headers, within 20 seconds.

Mail sent because a message arrived. Three things send mail after a message is stored in an Inbox. (1) With `smtp-server` `dsn` on (off by default), a recipient with `NOTIFY=SUCCESS` gets one "delivered" `multipart/report` sent to the envelope sender from `MAILER-DAEMON@` the listener's name, through the outgoing server of the first such account; it carries the message's whole header block; none is sent to an empty sender or one without `@`, or when no such account has a server. (2) `send#OutOfOfficeReplies` sends the account's automatic reply to the message's `From` address, once per sender in `replyOncePerDays` (4), not to list, bulk, automatic or bounce mail, a system sender, the account itself, or mail the rules moved to Junk or Trash; the subject is the reply's own, else `Automatic reply: ` and the mail's subject. (3) A rule's `forwardTo` action sends the message, with copies of its files, to the addresses the rule's author entered, from the account's default identity; it is skipped only when the mail's `From` is one of the account's own addresses. None of the three has a count limit per account or per hour, and none reads the stored authentication verdict. Rules run with authorization disabled, and an `EmailRuleAction` enumeration with an `optionValue` names a service that is called with authorization disabled and `emailMessageId`, `emailAccountId`, `emailRuleId`, `ruleOwnerUserId` and `value`.

An application's mail rule actions run on stored mail with authorization disabled, so mail from anyone reaches them. IronStone
Sales' lead intake address (`createLead`, Mantle `create#LeadFromEmail`) takes the team from the rule's value or the plus tag of a `To` or `Cc` address (`sales+leads@`), only a team
of an organization the rule's owner works for; the message makes a `SalesLeadIntake` row and a lead in that team's queue,
never a party, the sender's name and address held on the intake until the lead is qualified and blanked after the retention
days if it never is (`purge#LeadIntakes`); its `Message-ID` is the intake's identity, so the same mail again makes no second
lead. The mail text decides only the lead's name and description. The request for quote address (`createQuoteRequest`, Mantle `create#QuoteRequestFromEmail`) takes the team the same way, its rule's owner holding `SALES_QUOTE_EDIT` when the rule is saved and each time it runs, and makes an `RqtQuote` request in that team's queue with the message and its files on it, never a party (the sender is matched to an account or to the contact of exactly one account of the organization); the same `Message-ID` again makes no second request. A decline is mailed as the system only from such an intake mailbox, or one the rep may send from, to the address the rep previewed, once per request. The acknowledgement of such a request (off unless the organization's SalesPolicy turns `rfqAcknowledge` on) is a transactional delivery-ledger message from the organization, so its suppressions apply, queued at most once per request, only when the sender matched a contact or account of the organization and only to the mail's From address (an unknown or forged sender gets nothing back), never to automatic, list, bulk or system mail, marked `Auto-Submitted: auto-replied`; its locked text sees only the request's reference and the seller's name, nothing of the mail's content.

`send#EmailTemplate` (and `send#Email`) take a call's own `subject`, `fromAddress`, `fromName`, `bounceAddress` and `emailServerId` over the template's (mr-boss impl-marketing P6, F17). The service has `authenticate="anonymous-view"`. One screen path passes request parameters to it: the `emailScreenAsync` transition, through `send#ScreenRenderEmail`, which hands on only its own declared parameters ([Send services](#send-services)). The tools REST `email/templates/{id}/send` reaches `send#Email`, whose caller can already make a template with any sender and relay. The checks are the caller's: only Mantle's delivery ledger passes a sender, relay and bounce address, from the sending profile its delivery names, which `queue#Delivery` requires to be the delivery's organization's; a profile is stored only by a holder of `MESSAGE_SENDING_CONFIGURE` for an organization they work for, and names a relay that is an `EmailServer` no mail account owns, never a mail account's server or credentials; no profile answer carries a host, port, user or credential. A value with a CR or LF is left out (the subject's line breaks become spaces), an address must have an `@`, and the transport parses the addresses again, so a call cannot add a header or a recipient. A call's subject is used as given, never expanded with `bodyParameters`, so text a person wrote never runs as an expression.

`org.moqui.mail.EmailServices.read#DeliveryReport` reads a stored message as a delivery status notification (RFC 3464) or an abuse report (ARF, RFC 5965) from its stored report part and returned message (at most 256 KiB of each, 100 recipients), never its body text, and changes nothing; it is internal. The parsers (`report.rs`, `edge_mail::parse_dsn`) read hostile text without panicking (lossy UTF-8, no indexing past a part).

Mantle's bounce intake (`process#DeliveryReport`, the email ECA `DeliveryReportIntake` and the job `run_DeliveryReports`, as the system) reads only the messages of a bounce account (a hosted or shared account `bounces@` a sending profile's bounce domain); a report in any other mailbox is its owner's mail, left alone and not recorded. Anyone can mail a bounce address, and delivery ids are a sequence, so a report names its delivery only by the VERP address `bounces+(deliveryId).(bounceKey)@` the domain with the delivery's own random key (the address it came to, or an ARF's `Original-Mail-From`), or by the returned message's random `Message-ID`; a DSN counts only the recipients that are the delivery's own address. What a report can do is fixed by its delivery, never by the report: a hard bounce suppresses the delivery's address for every organization (a hard bounce stops all mail, the user's call), a complaint for the delivery's organization (promotional mail only), a soft bounce or a delivery nothing; each message is read once. A forger who has the key or the `Message-ID` (the recipient, or who saw the message) can only suppress that recipient's own address. The edge relay's bounce (`ES_BOUNCED` on a sent message) is matched by the attempt that sent it. `find#DeliveryReceipts` answers a delivery reviewer (`MESSAGE_DELIVERY_REVIEW`), a suppression reviewer or a contact administrator only the deliveries of the organizations they work for (every one for a system administrator or a holder of MARKETING_ALL_ORGANIZATIONS; another organization's delivery answers as missing), with any address in a diagnostic struck out.

`poll#EmailServer` (job `poll_EmailServer_frequent`) is paused. If unpaused, the cron is every 15 minutes, `emailServerId=SYSTEM`, `authenticate="anonymous-all"`. It connects out to the configured IMAP or POP server. `sync#DueEmailAccounts` (job `sync_EmailAccounts_frequent`) is running, every minute, `authenticate="anonymous-all"`; the job is its caller. IMAP IDLE is on by default (`idle-enabled="true"`, `idle-max` 8) and dials the account's server. It does not listen. Both jobs use the scheduler's authorization-off path.

OAuth mail sign-in is not a listen port. It stays off until the operator sets a Google or Microsoft client id and secret. The browser session, PKCE, and server-side state (10 minutes, single use) protect the callback `/emailOAuth/callback`. The redirect URI is the deployment's and is never taken from the request. A server with no field encryption refuses to store the refresh token. The `callback` transition (`webroot/emailOAuth.xml`, `read-only="true"`, `require-session-token="false"`) passes `state`, `code`, `error` and `error_description` to `complete#OAuthSignIn` (`anonymous-all`) and nothing else. The state is compared in constant time with the sign-ins kept in the caller's session (at most 8), taken once, and refused for another user, a signed-out caller or after ten minutes. The page it sends has a nonce CSP (`default-src 'none'`), `no-store`, the outcome text HTML-escaped and no token; it posts the outcome to `window.opener` on its own origin and on the BroadcastChannel `moqui-email-oauth`. The ID token comes from the token endpoint; its audience, issuer, expiry and nonce are checked, its signature is not.

## Send services

`org.moqui.mail.EmailServices.send#EmailTemplate` (`authenticate="anonymous-view"`) and `send#Email` (default authentication) are one implementation, `moqui_mail::send_template` (`crates/moqui-mail/src/implementation.rs`). The recipients are the call's `toAddresses`, `ccAddresses` and `bccAddresses`, with the template's cc and bcc added. The sender, the subject and the relay are the template's, or the call's over them. The body is the template's `bodyScreenLocation` rendered with the call's parameters and its `bodyParameters` in the script context, or the call's `body` and `bodyText`. The template's `fromAddress`, `fromName` and `subject` are expanded as `${expression}` text. An attachment's `fileName` is expanded the same way, a call's `attachments[].fileName` included (`push_parameter_attachment`, `render_attachment`); `moqui_core::script::expand` runs each `${expression}` in the script runtime. An attachment is a call's `contentText` or `contentBytes`, a screen rendered in `screenRenderMode` (`attachmentLocation` or `screenPath`), or the bytes at `attachmentLocation`. `extraHeaders` adds a field only when its name is at most 76 ASCII letters, digits or `-`, is not a field the message writes itself, and its value is under 998 bytes with no line break. `inReplyTo` is kept only when it is one message id. Each address is parsed by lettre (`mailbox`). Of a stored message's `headersString` only a fixed list of names (`CLIENT_HEADERS`) is sent, each a single line under 998 bytes. Links in a template's body start with `https://` and the template's `webHostName`, else the `EmailServer`'s `webBaseUrl`, else the conf webapp's root URL; a request's host is not used (`RenderEnv::new`). When `createEmailMessage` is not false (the interface default is true) the rendered body is stored in `EmailMessage.body` and `bodyText`, with authorization disabled. The instance fence (`fence::check_effect`, `Effect::Mail`) is checked first.

`send#ScreenRenderEmail` (default authentication) takes `screenLocation`, `screenRenderMode`, `fileName`, `toAddresses`, `ccAddresses`, `bccAddresses`, `emailTemplateId` (default `SCREEN_RENDER`), `createEmailMessage` (default false), `bodyParameters` and `title`. It makes one attachment `{fileName, attachmentLocation: screenLocation, screenRenderMode}`, sets `pageNoLimit` and `lastStandalone` in `bodyParameters`, and calls `send#EmailTemplate` with its context. A call's attachment file name is taken as written; only an `EmailTemplateAttachment` row's own is expanded (SEC-MAIL-61, fixed). The `SCREEN_RENDER` template's subject is `${title}` and its relay is the `SYSTEM` server.

`send#EmailMessage` (`send_message`, default authentication) takes an `emailMessageId` and, with authorization on, answers a message the caller may not send as one that does not exist (`may_send`): system mail (no `emailAccountId`) only when `ES_READY` or `ES_BOUNCED`, or any for an `ADMIN` (the message page's Resend), and an account's message only when `ES_READY` or `ES_BOUNCED` and the caller has send level on that account (`get#EmailAccountAccess` `canSend`). Internal work (authorization disabled: the queue, its retries, the client's delivery) is not checked (plans/Security-Review.md SEC-MAIL-64, fixed). It refuses a message in `ES_DRAFT` or `ES_CANCELLED` and one with no body, no from address or no to address; a message in any other status is sent through its own `emailServerId`, else its mail account's server. The server's `allowedToDomains` drops recipients outside it. Only a message in `ES_READY` or `ES_BOUNCED` changes status (to `ES_SENT`) after the send.

## System mail with passwords, codes and links

- `org.moqui.impl.UserServices.reset#Password` is `authenticate="anonymous-all"`. It finds the account by `userId`, then `username`, then `username` as an email address, and answers the same public message whether or not one is found. One reset is made per `loginRules.disableMinutes` after `resetPasswordSetDate`. The reset password is 12 random characters, stored hashed in `UserAccount.resetPassword`; the current password stays valid. The mail (`PASSWORD_RESET`, body screen `PasswordReset.xml`) carries the reset password as text ("Your reset password has been set to: ..."). The call does not pass `createEmailMessage`, so the body with the password is stored in an `EmailMessage` row. `password/@email-expire-hours` is 48 in the default conf.
- The single-use code mail (`SINGLE_USE_CODE`) carries the code and its `thruDate` to the factor's address; a second mail (`ADDED_EMAIL_AUTHC_FACTOR`) goes to the account's main address when the two differ. Neither call passes `createEmailMessage`.
- The public account registration (`org/moqui/public/Account.js`) mails a 64-character random `verificationToken`. Its hash is stored (`RegistrationChallenge.tokenHash`), it expires after one hour, earlier challenges of the user are consumed when one is made, and a consumed or expired one is refused. The call does not pass `createEmailMessage`.
- A Mantle invitation (`mantle/party/Invitations.js`) mails a link `{base}/i/{token}` with a 43-character random token whose hash is stored and which has an `expiresDate`; a resend makes a new token. The call passes `createEmailMessage: false`. The base is the caller's `baseUrl`, else the template's `webHostName`, else the `EmailServer`'s `webBaseUrl`. The mr-boss screens pass `ec.web.getWebappRootUrl()`, which takes a request's `Host` header only when a `root-screen` of the webapp names that host (`crates/moqui-core/src/web/mod.rs` `webapp_root_url`), and else the conf's host.

## Mail client

The mail client (`org.moqui.mail.EmailClientServices`, screens under `BasicComms/Inbox` and `BasicComms/Settings/MailAccounts`) is reached by members of `BASIC_COMMS_USERS`, `BASIC_COMMS_ADMIN` and `ADMIN` through the `BASIC_COMMS` artifact group (`inheritAuthz` Y from `BasicComms.xml`). The services check the account, not the screen: `get#EmailAccountAccess` answers the accounts a user owns (`ownerUserId`) or has a current `EmailAccountUser` row on, with level 1 (`EapRead`), 2 (`EapSend`) or 3 (`EapManage`). A `userId` other than the caller's is taken only with authorization disabled. `get#Thread` and `resolve#MessageTargets` find messages only with `emailAccountId` in the caller's accounts; another account's message is "not found". `find#Messages` refuses a named account that is not in the caller's access map. `export#EmailMessage` needs level 1 on the message's account, or authorization disabled for a message with no account. `InboxServices.get#MessageDetail` answers a message with no account (system mail) only to a member of `ADMIN`. The screens call `org.moqui.comms.InboxServices.run#Operation`, which takes an operation name from a fixed list and hands it to an app's `inbox-source` provider when one is declared, else to the framework service.

Drafts and sending. `save#Draft` changes a draft only at level 2 on the draft's account. The identity it names must be of an account the caller reaches and of the named account, and the account must be one the caller may send from (`canSend`). The draft's `fromAddress` is the identity's address, else the account's; the request cannot set it. An attachment location must be on the draft already or start with `dbresource://email/{emailAccountId}/` with no `..` segment, unless authorization is disabled. A `parentEmailMessageId` must be a message of an account the caller reaches. `send#Draft` asks the same access and `canSend`, an identity of the draft's account, and an `EmailServer` with an `smtpHost`; it sends a message in `ES_DRAFT`, or in `ES_READY` with a `sendError`. `deliver#DraftMessage` and `claim#DraftSend` refuse a call unless authorization is disabled. `send#DueDrafts` (`anonymous-all`) with an `emailMessageId` and authorization not disabled asks level 2 on the message's account. `create#EmailIdentity` asks level 3 on the account and an address that contains `@`; the address is not checked further. `create#EmailAccount` takes an existing `emailServerId` only with authorization disabled, so a user sends through a server whose host and sign-in the user gave.

## Message display and files

A message's HTML is never put in the application's document by the mail client. In the qvt client `m-html-view` cleans it in the browser with DOMPurify (HTML profile only; no `style`, `form`, `iframe`, `object`, `embed`, `base`, `link`, `meta`, `script`, media tags; no `srcset`, `poster`, `ping`, `action`, `srcdoc`), rewrites images, links and CSS, and shows it in an `iframe` with `sandbox="allow-same-origin allow-popups allow-popups-to-escape-sandbox"` (no `allow-scripts`) whose `srcdoc` has a CSP of `default-src 'none'; img-src data:` (plus `https: http:` when remote images are allowed), `style-src 'unsafe-inline'`, and `referrerpolicy="no-referrer"`. If DOMPurify does not load, the text is shown. The server does not clean the HTML for the qvt client. In `html` render mode the server cleans it (`StringUtilities.cleanHtml`) and writes an `iframe` with `sandbox="allow-popups allow-popups-to-escape-sandbox"` and `img-src data:`. In `html-print` mode the text is escaped. Remote images are loaded by the browser, never by the server: they are hidden until "Show images", and shown at once when the user's `remoteImages` preference is `always`, the `From` address is in the user's trusted senders, or the `From` address is one of the user's own (`Mail.qvue`); the stored authentication verdict is not part of that test. `cid:` images are fetched by the page from the `attachment` transition with the session and put in the frame as `data:` URLs. `Inbox/MessageDetail/attachment` (GET, read-only) serves an `EmailMessageAttachment` only when `get#Thread` shows its message to the caller, through `ec.web.sendResourceResponse`, which sends a type that can run script (HTML, SVG, XML, JavaScript) as an attachment whatever `inline` says. `Inbox/MessageDetail/downloadEml` (read-only) sends `export#EmailMessage`'s text as `message/rfc822`; for system mail it disables authorization after `get#MessageDetail` has answered the message. The mr-marble `PartyEmails.xml` `EmailMessage` transition is a second display path, with none of the above ([Send services](#send-services)).

## Mail account servers and other outbound requests

A user who adds a mail account names its incoming host and port (`storeHost`, `storePort`, IMAP or POP3) and outgoing host and port (`smtpHost`, `smtpPort`); `create#EmailAccount` writes them to an `EmailServer` the account owns. The server connects to them on the wizard's test (`test#EmailServer`), on `sync#EmailAccount`, from the job `sync_EmailAccounts_frequent` every minute, from the IDLE workers and on each send. `email-client` `allowed-hosts` limits the hosts and is empty by default, which allows any host (`implementation.rs` `require_host`). SMTP, IMAP and POP connect through `inbound::connect_tcp`: one lookup, every address checked, the connect to one of them; an internal address is refused when the row is denied the private network (`implementation::private_network_denied`: `N`, or anything but `Y` on a production instance), and the account services never give an account-owned server `Y`, and a link-local or metadata address is refused always (plans/Security-Review.md SEC-MAIL-02, fixed). The wizard's host pattern takes a name or an IPv4 literal. A test answers a fixed kind of failure (`implementation::test_failure_kind`: address not allowed, host not found, TLS failed, connection refused, timed out, sign-in refused, not a mail server) and logs the client's text at info; this server's own refusal of a plain store is shown as written.

- `discover#EmailServer` takes an address, checks its domain (`valid_domain`), and fetches `https://autoconfig.{domain}/mail/config-v1.1.xml`, the domain's `/.well-known/autoconfig/mail/config-v1.1.xml` and the Thunderbird ISPDB within 3.5 seconds; the domain's own URLs are fetched only to public addresses (`deny_internal_addresses`), not when `email-client` `autoconfig-urls` replaces the list. Its SRV and MX queries go by UDP, on a connected socket with a random id, to the first nameserver of `/etc/resolv.conf` or `email-client` `dns-server`, within 1.5 seconds.
- `unsubscribe#Message` (send level on the message's account) posts `List-Unsubscribe=One-Click` to the first `https` address of the message's `List-Unsubscribe` header when `List-Unsubscribe-Post` allows it, only to a host the script takes as public and with `denyInternal()` on the call, within 20 seconds; else it sends a message from the account to the header's `mailto` address with that address's subject and body.
- `import#EmailMessages` takes uploads (`file`, `fileList`), `messageText`, and `location` or `locationList`, which are read through `ResourceFacade::open` with no check of the location; the one screen that calls it (`Settings/MailAccounts/Account.xml`) passes `emailFolderId` and `file` only.
- The mail capture (`MailCaptureToolFactory`, in the default conf; `service/mail_capture.rs`) captures only in a `moqui test` run (`mail_capture::allowed()`, a process flag the test runner sets and no server sets): there `mail_capture_sends=true` or `ec.factory.getTool('MailCapture').enable()` turns it on, and `send#EmailMessage` then marks the message sent, connects to nothing and keeps the last 500 messages in memory. On a server `enable()` returns an error and the property is ignored with a warning (plans/Security-Review.md SEC-DEV-05, fixed).

## Tools REST mail resources

`/rest/s1/moqui/email` (group `MOQUI_API`, `ADMIN` only): `messages` lists and reads `EmailMessage` rows of every account and of system mail (at most 100 a page unless `pageNoLimit`), and patches one; `templates` lists, creates and patches `EmailTemplate`, and `templates/{id}/send` calls `send#Email`; `servers` and `servers/{emailServerId}` are read through services (`EmailServices.find#RelayServers`, at most 100, and `get#RelayServer`), which neither list nor answer a server a mail account owns (`EmailAccount.ownsEmailServer`), as the connection services do, and answer each encrypted field as `<field>IsSet`, never `mailPassword`, `smtpPassword` or `oauthRefreshToken` (plans/Security-Review.md SEC-MAIL-04, fixed); `PATCH servers/{id}` is `EmailServices.update#RelayServer`: a caller not in `ADMIN` is refused (403), an account-owned or missing server is "not found", a relay whose mail goes out through the edge node (`smtpHost` `edge:`) or that signs in with OAuth is not changed (nor set so here), only the given fields are written and nothing is answered, and Admin's endpoint-change rule holds (a changed host, port, TLS setting, user or sign-in kind clears each stored password not given again, saves the relay disabled and waiting for a test in Admin's Connections, and on production sets `allowPrivateNetwork` N unless given; asking `disabled` N in such a change is refused); `servers/{id}/poll` calls `poll#EmailServer`, which answers an account-owned server as not found (`moqui_mail::poll_server`). Generic entity writes refuse an account-owned `EmailServer` too, an `ADMIN`'s included: `/rest/e1` (`query_rest::rest`) and Service REST entity resources (`service/rest.rs` `run_entity`) check `sensitive::account_owned_email_server` for a create, store, update or delete.

## Tracking pixel

`GET /email/{key}` has no authentication ([Routes](Attack-Surface-Routes.md)). The key is the message's view key, `{emailMessageId}.{tag}`, the tag 128 bits of an HMAC-SHA256 of the id under a key derived from `session_cookie_key` (`web::email_view_key`); the mail render puts it in a template's context as `emailViewKey` (mr-marble's `EmailLayout.html.fancy` is the one template with the image). A bare id or a wrong tag changes nothing. Only a message in `ES_SENT` is updated to `ES_VIEWED`, with `receivedDate` set to the time of the request and authorization disabled; queued (`ES_READY`) and received mail is left alone (plans/Security-Review.md SEC-RTE-01, fixed).

## MX delivery on an edge node

`crates/moqui-mail/src/mx.rs` delivers outbound mail straight to recipient domains when `edge_mail_mta` is `moqui` (`conf/edge/MoquiEdgeConf.xml` sets it). At most 8 deliveries run at once and 40 rows are taken a round; a session ends within 10 minutes and each command within 60 seconds; the wait between tries is capped at 4 hours.

| Outbound request | To | Limits and checks |
|---|---|---|
| SMTP, port 25 | Each MX host of the recipient domain by preference, each of its addresses in turn; the domain's own address when it has no MX. A null MX is refused (`556`). | An MX host's internal addresses are dropped, and a domain with only internal ones is refused, unless `mail_mx_override` names it ([Outbound](Attack-Surface-Outbound.md)). The instance fence is checked per host. With an MTA-STS policy in `enforce` mode only the hosts the policy names are tried. |
| STARTTLS on that session | The MX host | Opportunistic unless the domain has an MTA-STS `enforce` policy or is in `mail_mx_require_tls` (recipient domains, comma-separated, `*` for all; `mx.rs` `tls_required`): otherwise used when the host offers it, any certificate and any host name accepted (`dangerous_accept_invalid_certs(true)`, `dangerous_accept_invalid_hostnames(true)`), a host that does not offer it gets the message in clear, and when STARTTLS fails the session is opened again and the message is sent without TLS. With an `enforce` policy or a listed domain the certificate must be valid for the host, and no STARTTLS, a failed handshake or an invalid certificate ends that host's try: the message waits and bounces after `mail_delivery_days` rather than go in clear text. `mail_mx_require_tls` applies with `mail_mx_override` too. |
| `GET https://mta-sts.{domain}/.well-known/mta-sts.txt` | The recipient domain's policy host | 30 seconds, no redirects followed, at most 64 KiB read. The `_mta-sts` TXT record's id decides when it is fetched again. |
| `mail_mx_override` (`domain=host:port`, `*` for any) | The named host and port | Skips the MX lookup and MTA-STS. No instance purpose is checked in `override_for`. |

A host's failure text is kept as `{host} [{ip}]: {reason}` with the remote's reply in it, and is the answer every recipient of the try gets; the reply sent back to the local node in the `mailStatus` report is cut to 16 KiB (`MAX_REPORT`).

## DKIM signing and internal verification

The DKIM key is the property `mail_dkim_key` (an RSA key, PKCS#8 in base64 or PEM); a node set to make one generates RSA 2048 and writes it to `runtime/.env` (`crates/moqui-mail/src/auth.rs`). The selector is `mail_dkim_selector` (default `moqui`). A message is signed for its `From` domain when that domain is in `mail_dkim_domains`, or, when that list is empty, when it is the domain of a hosted or shared account (`signing_domain`). A message whose key cannot be had goes unsigned and is still sent. `verify_internal` (called from `delivery.rs` and `edge_mail.rs`) reads a stored message's DKIM signatures of the node's own selector, verifies them against the node's own key with no DNS query, and writes an `Authentication-Results` field under the node's authserv-id when one passes. Inbound verification (`verify`) reads at most 10 signatures and ends within 45 seconds; a check that does not finish is a `temperror` verdict.

## Message parsing and storage

`crates/moqui-mail/src/store.rs` `parse_message` parses with `mail_parser::MessageParser::default()`; `store.rs` sets no limit of its own on parts or nesting. An empty message and one with no header fields are refused. The stored header block is at most 65,536 bytes (`HEADERS_MAX`). An attachment is written to `dbresource://email/{account}/{message}/{n}-{name}`; in the name control characters and `/ \ ? # % :` become `_`, leading and trailing dots are cut, and at most 120 characters are kept (`safe_segment`). Mail accounts have no storage quota (the `get#InboxData` description; the code was not traced).
