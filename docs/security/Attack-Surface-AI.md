# Attack surface: LLM, A2A, MCP and Assist

The model facade, A2A, MCP, the OpenAI-compatible gateway, Assist and the agent permissions. This is one file of the attack surface map. The index, how to read a row, the defaults and the lock-down advice are in [Attack-Surface.md](Attack-Surface.md).

## LLM, A2A, MCP and Assist

Routes exist when the `llm` feature is compiled. While a protocol is off, its handlers answer 404. `llm-facade` `enabled` is `true`. That element is the model facade. It is not the A2A server, the MCP server, or the gateway. Assist answers 503 when the facade is disabled; `bootstrap` still answers (`docs/ai/Assist.md`).

A user with `EXTERNAL_USER` never holds `AgentUse`, `AgentAdmin`, `AgentAudit`, `LlmGatewayUse`, `A2aServerUse` or `McpServerUse` (`EXTERNAL_WITHHELD` in `crates/moqui-core/src/user/preference.rs`), so that user starts no run and gets no model call. `start_run` (`crates/moqui-llm/src/run/mod.rs`) and `LlmFacade::complete` (`crates/moqui-llm/src/lib.rs`) refuse that user again. `AgentSkillAuthor` is not in the list. The embedding path ([Semantic find](#semantic-find)) does not make the check.

### A2A

Off. `a2a_enabled` is `false`, and `trust-forwarded-headers` is `false`. While it is off, `/a2a` and `GET /.well-known/agent-card.json` answer 404.

From `docs/ai/A2A.md`, with the login in `crates/moqui-llm/src/a2a/mod.rs` `log_in` and the limits in `crates/moqui-host/src/llm/a2a.rs`: a caller needs `A2aServerUse` and `AgentUse`. Credentials are a Bearer login key, an `api_key` or `login_key` header, or Basic with an app password or a login key as the password. The account password is refused (401). Credentials are taken only over TLS, a believed proxy's https, or from a client on this machine (behind a believed proxy, the client it names in `client-ip-header`, never the socket peer). Missing credentials are 401 `WWW-Authenticate: Bearer realm="a2a", Basic realm="a2a"`. No permission is 403. The body max is 4 MiB. Waits and streams are at most 256 on a node (503) and 16 per user (429). Every request except the public card needs `A2A-Version: 1.0`. OIDC is not built. An agent is reached only when `exposeA2a="Y"` and the surface includes `a2a`. The seed `assist` agent does not. Writes wait for the human owner.

Credentials over plain HTTP from a client that is not on this machine answer 403 before they are read. The secure test is the host's `http::secure_transport` (TLS, a believed proxy's `X-Forwarded-Proto: https`, or a client on this machine), which A2A, MCP and the gateway share. Behind a believed proxy the client is the address the proxy names in `client-ip-header`, never the loopback socket peer; a request the proxy passes without naming a client is not local. The public card is `Cache-Control: public, max-age=300` with `Vary: Host`. With `a2a_public_url` empty, the card's URLs are built from the request's `Host`, which is checked for its characters only (`crates/moqui-llm/src/a2a/card.rs` `base_url_of`). `X-Forwarded-Host` and `X-Forwarded-Proto` are read only from a believed proxy and only with `trust-forwarded-headers`. The card advertises `streaming`, `pushNotifications` and `extendedAgentCard`. Every task lookup is filtered by the caller's user id and the `a2a` surface.

**Push notifications.** An A2A caller may give a push URL on `SendMessage` or through the push config operations. `check_url` in `crates/moqui-llm/src/a2a/push.rs` takes an absolute `http` or `https` URL with no user info or fragment, at most 2000 characters. It is `https` unless `push allow-http` is true or `push allow-hosts` names the host (defaults: `false`, empty). An internal address written in the URL, `localhost` and `*.localhost` are refused unless `allow-hosts` names the host. The server POSTs each task update to the URL from an outbox, with `A2A-Version`, the caller's `token` in `X-A2A-Notification-Token`, the caller's `authentication` as `Authorization: <scheme> <credentials>`, and trace headers. The client refuses internal addresses at connect time ([the guard](Attack-Surface-Outbound.md#the-internal-address-guard)), follows no redirect, connects within 3 seconds, and reads at most 16 KiB of the answer. `push timeout` is 15 seconds and `max-attempts` is 6. A task takes at most 10 configs and a caller at most 50. `token` and `authenticationJson` are encrypted fields of `AgentPushConfig`, and a config's wire object never carries them.

### MCP

Off. `mcp_enabled` is `false`, and `trust-forwarded-headers` is `false`. While it is off, `/mcp` and its documents answer 404.

From `docs/ai/MCP.md`, with the checks in `crates/moqui-llm/src/mcp/server.rs` and `crates/moqui-host/src/llm/mcp.rs`: a caller needs `McpServerUse` and `AgentUse`. Credential shapes match A2A, with realm `mcp`. No credentials is 401 JSON-RPC `-31401`. No permission is 403 `-31403`. `server/discover` needs no credentials. The body max is 4 MiB. The transport is `POST /mcp` only; GET and DELETE are 405. The seed agent `mcp` serves `mcp` with `exposeMcp="Y"`. The MCP client cannot approve a write. Public when on, and cached for an hour: `GET /mcp/server-card`, `/mcp/setup`, `/.well-known/mcp.json`, `/.well-known/ai-catalog.json`.

Before the body is read, a present `Origin` that is not this machine, the configured origin or an allowed origin answers 403; the request's own `Host` is never the test. A content type other than `application/json` is 415. `MCP-Protocol-Version`, `Mcp-Method` and, for `tools/call`, `Mcp-Name` must match the body, or the answer is 400. Only `server/discover`, `tools/list` and `tools/call` are served. The four public documents carry `Access-Control-Allow-Origin: *` and `Vary: Host, X-Forwarded-Host, X-Forwarded-Proto` (`mcp::server::public_reply`). With `mcp_public_url` empty their URLs are built from the request's `Host` (`crates/moqui-llm/src/mcp/mod.rs` `base_url`). A write waits for its owner: the call answers `input_required` with a `requestState`, an HMAC-SHA256 over the approval, the user, the tool, the digest of the arguments and the expiry (`crates/moqui-llm/src/mcp/state.rs`). The key is `mcp_request_state_key` (base64, 32 bytes or more), else a key derived from `webapp-list/webapp[webroot]/session-config@cookie-key`, else a random key of the process. A state over 4096 bytes is refused. The MAC is compared in constant time.

### Gateway

Off. `llm_gateway_enabled` is `false`. The live element is `<gateway enabled="${llm_gateway_enabled}" require-client="true" timeout="300"/>`. An `enabled="true"` example above it in the conf is inside a comment.

From `docs/ai/Gateway.md`, with the login in `crates/moqui-llm/src/gateway.rs` and the body limit in `crates/moqui-host/src/llm/gateway.rs`: Bearer login key or app password, or Basic with those. The account password is refused. TLS, a believed proxy's https, or a client on this machine (behind a believed proxy, the client it names). Missing or bad credentials are 401 `invalid_api_key`. The caller needs `LlmGatewayUse` and an `LlmApiClient` row. An app password always needs a client. An account's login key needs one because `require-client` defaults to true; a key made for the gateway alone (`create#UserScopedKey`, `UserLoginKey.scope` `gateway`) is its own client, since it opens nothing else and its user's permission and quota still apply. The body max is 16 MiB. The path is exempt from the webapp request deadline. The gateway `timeout` of 300 seconds answers 504. Paths: `GET /models`, `GET /models/{alias}`, `POST /chat/completions`, `POST /responses`, `POST /embeddings`. An unknown alias is 404. No tools run on the server: function-tool definitions pass through, and any other tool type is 400 `unsupported_tool`.

### Assist

The drawer is screen transitions on `assist.xml` (`require-authentication="false"`), not host routes. Thirty-one of its 33 transitions call `AssistServices.call#Drawer` with authorization disabled. `constitution` and `constitutionReference` call the Constitution readers for any signed-in user, with no `AgentUse` ([Constitution services](#constitution-services)). `mentions` with `kind=records` calls `sri.getShellSearch` after its own `AgentUse` check. GET reads: `bootstrap`, `constitution`, `constitutionReference`, `conversations`, `conversation`, `tasks`, `prompts`, `mentions`, `attachment`, `memories`, `skills`, `events`, `read`. POST: `turn`, `cancel`, `retry`, `follow`, `context`, `submitted`, `decide`, `preview`, `answer`, `feedback`, `queued`, `attachments`, `transcribe`, `textAction`, `memory`, `skill`, `canvasState`, `canvasAction`, `canvasAdjust`, `canvasProblems`.

`docs/ai/Assist.md` is the contract for those calls. The browser session cookie is the login. Every call acts for the current user and needs `AgentUse`. Another user's conversation, run, approval, question, hand-off, or message is 404. A call from inside a run is 403. POST requires `X-CSRF-Token` or `moquiSessionToken`, and a missing token is 401 `Session token is missing or is not valid` before the call. The qapps shell includes the drawer when the llm feature is on and the user has `AgentUse`.

Every drawer call goes through `Caller::current` in `crates/moqui-llm/src/assist/mod.rs`. It refuses a context that an agent's run works in (403), a request with no user (401), and a user without `AgentUse` (403). A conversation or a run is loaded with authorization off and then compared with the caller's user id; a mismatch is 404. Each write in `assist/write.rs` resolves its id through the caller, and a canvas is found through the caller's conversation (`assist/canvas.rs` `canvas_of`). `decide`, `canvasAction` `kind=arm` and `kind=mutation` also need `Decider::from_request` (`crates/moqui-llm/src/approval/mod.rs`): a browser render with its session token or the terminal, never a header login, an agent's context or internal code. `attachment` sends a file only when the stored `userId` is the caller's, as `Content-Disposition: attachment` with `X-Content-Type-Options: nosniff`. A message is at most 16,000 characters. A turn that starts a run counts one hit of the `AT_LLM` tarpit `agent:<agentId>` (30 a minute, then 300 seconds). `transcribe` and `textAction` count `assist:<call>` (60 a minute). The drawer's audio for `transcribe` is at most 10 MiB (`max-audio-bytes`).

**Dev Assist's `hosting` tool** (the dev-aide crate, `src/agent/hosting.rs`; plans/design-dev-aide.md 21.8) reads a working tree's hosted repository on a connected group server as the connected user: merge requests, review threads, checks, a job's log and failed tests, an issue. Every text it returns is other people's (titles, descriptions, comments, logs, test messages): it reaches the model inside `<untrusted from="group-server">` with the wrapper's markers elided (`moqui_llm::prompt::untrusted`), so a comment that tells the agent to approve or push is data. It has no action that approves, merges, re-runs, resolves a thread, signs the contributor agreement or pushes. It gives an agent no diff (files, file texts, commits) of a merge request whose commits' authors have not all signed where the server requires it (`get#AuthorSigned` per author email, or the application's `diffRefused`), nor when the authors are not all known: no commit list, a cut one (`commitsTruncated`, fewer commits than `aheadBy`), a commit with no author email, more than 20 authors, or, for a repository an application keeps, an author the server did not decide (`known` false, which is also its answer when its agreement hook fails); the threads of such a merge request come without their line's text and without fenced or quoted code (a suggestion). A worktree of an agent's session is its maker's: it is made only for one of the caller's own conversations, only that user's session is rooted in it, only they or an administrator remove it (and only under `runtime/worktrees`), and a session with a worktree reaches neither another worktree nor a root inside the tree its worktree stands in for. Its reads run under the read fence: the tool opens a remote permit for the hosted server's origin only (`fence::enter_remote`), and the Dev AIDE's client lifts the fence for that one GET after `check_remote` passes (never in a sim, never for another origin, never for a write); a read that would write (resolving a root's hosted repository) is refused under the fence instead. A comment, a reply or a new merge request is an EXTERNAL approval whose card shows the text, the merge request, file and line, the repository and the server; the approved write goes through the same HostingServices as the Workspace's, so a header login, a fence and a sim refuse it.

`GET /assist/runs/{run_id}/events` and `.../events.json` authenticate like `/notws` (origin, session cookie, else `login_key`). The stream is for the run's owner. The routes check the run's owner only (`crates/moqui-host/src/llm/sse.rs` `owns`); they do not check `AgentUse`. At most 256 streams on a node (`MAX_STREAMS`; one more is 503 with `Retry-After`, `docs/ai/Assist.md`) and 16 of one user (`MAX_STREAMS_PER_USER`; one more is 429 with `Retry-After`).

`GET /assist/sandbox` is public and has no session. The origin written into the policy is the scheme and the host of the request: `X-Forwarded-Host` from a believed proxy, else `Host`, else the webroot's configured host (`crates/moqui-host/src/llm/sandbox.rs` `frame_host`). A host that is not a plain name and port is 400. Query `v` is a cache buster. `x=1` adds `https:` to `img-src` only. The iframe is `sandbox="allow-scripts"` without `allow-same-origin` (`docs/ai/Assist.md`). The policy is the frame document, separate from the screen CSP:

```
sandbox allow-scripts; default-src 'none';
script-src <origin>/libs/vue/ <origin>/libs/quasar/ <origin>/js/WebrootAssistSandbox.js 'unsafe-eval';
style-src <origin>/libs/ 'unsafe-inline'; font-src <origin>/libs/;
img-src data: <origin>/images/ <origin>/libs/;
connect-src 'none'; media-src 'none'; object-src 'none'; frame-src 'none'; child-src 'none'; worker-src 'none';
manifest-src 'none'; form-action 'none'; frame-ancestors 'self' <origin>; base-uri 'none'
```

Response headers from that doc: `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`, a `Permissions-Policy` that turns features off, and no `X-Frame-Options`. `'unsafe-eval'` is in this frame policy. It is not in the default screen CSP.

Mantle's `user-facts` provider (`mantle.party.UserFactServices.get#OrganizationFacts`, named in Mantle's MoquiConf `llm-facade`) adds to a new conversation's prompt the names and ids of the user's internal organizations (at most twenty) and their active one; it reads only and answers nothing for another user. Mantle's conf is its one caller: no screen or rest-api file names it. A tool still takes and checks its organization: the facts are fixed when the conversation starts.

### Agent runs and tools

A run's step logs in as the run's user (`internal_login_user`, `crates/moqui-llm/src/run/step.rs`) on an agent pool thread. A job or trigger run acts as the agent's or the trigger's `runAsUserId`; only an internal caller sets that (`crates/moqui-llm/src/run/mod.rs` `acting_user`). A service becomes a tool only through an `AgentToolExposure` row, which `org.moqui.agent.AgentAdminServices.store#AgentToolExposure` (`AgentAdmin`) writes. One row is seeded: `get_constitution_references`, READ. Before a service tool runs, `user_permitted` (`crates/moqui-llm/src/tools/catalog.rs`) calls `authorize("AT_SERVICE", ...)` for the current user, and for an entity-auto service `authorize("AT_ENTITY", ...)`. That check is skipped for a service whose `authenticate` is `false` or anonymous: once such a service is exposed, the agent of every `AgentUse` user may run it, and an agent's role group is the only bound. The service then runs with default call options, so authorization is on. An agent's role group, when it has one, also has to permit the service (`group_permits`). A READ tool runs under the read fence. Any other class asks for an approval; DESTRUCTIVE needs the policy's `allowDestructive`. The `screen`, `data` list and `search` tools render `/apps` screens as the run's user with every write held by the transition gate. The `data` tool also reads the entities of the conf's `data-entity` patterns with authorization off (`crates/moqui-llm/src/tools/data.rs`): by default the package `moqui.basic` (enumerations, statuses, units, geos, localized messages). Encrypted fields are never read, and fields named like secrets only with `secret-fields="true"`. Screen sessions are at most 64 on a node and 4 for a user.

### Approvals

A write waits as an `AgentApproval` row (128 random bits as its id) for at most `approval-ttl-minutes` (30). `approval::decide` (`crates/moqui-llm/src/approval/mod.rs`) takes a decision only from the approval's own user, with one exception: a chat run's card. A run started from a room message runs as the sender, and its approval card is a room message. A member who may post in the room (`get#RoomAccess` `canPost`) decides that card through `org.moqui.agent.AgentServices.decide#ChatCard` (the webroot `chatAssistCard` transition, a POST), other than an agent's chat or run-as user, a member with the role `CmrAgent`, or an `EXTERNAL_USER` (`crates/moqui-llm/src/chat.rs` `room_approval`). A member who is not the requester approves only a write that member may make, checked as that member (`approval::decide_in`, `decider_may_write` under `user::as_user`: a screen write's path, a service's own permission); a write of another system's tool, an add-on tool or a change set only its requester approves. Any such member may reject (plans/Security-Review.md SEC-AI-01, fixed). The write still runs as the user who asked, with that user's permissions; the approval keeps both users. Edit in screen and a question's answer stay the requester's. A decision needs a browser render with its session token or the terminal (`Decider::from_request`). A policy rule approves by itself only for a background agent: the run is on the `job` surface and every surface the agent serves is `job` (`is_background`). A click on a Button of an OpenUI canvas holds the write and shows it; the user's confirm of that held write is recorded as an approval through the channel `canvas`, with no card ([Canvases](#canvases)). A skill's `risk` (`reversible`, `confirm`, `irreversible`) is a label on the card; it neither adds nor skips an approval. A learned skill counts as `confirm` whatever it says.

### Canvases

An agent on the drawer may write a canvas. With no `canvasDialects` an agent writes only OpenUI Lang; the seed `assist` agent names none. Vue SFC is off unless an agent names `vue-sfc`. The server parses an OpenUI program in a JavaScript runtime of its own with no `ec` and no host functions, a 64 MiB heap and a 5 second limit (`crates/moqui-llm/src/ui/openui.rs`). A Vue SFC script is compiled, not run, in one with 16 MiB and 2 seconds (`ui/vue_sfc.rs`). A program is at most 64 KiB. A canvas reads through `GET /assist/read`, as the user. A canvas never posts from the page (`ui/write.rs`). A Mutation names a transition under `/apps`. The model writes the Button's label and the Mutation behind it, and a Mutation's arguments may be literals in the program. The server evaluates the arguments from the stored program and the posted state, holds the request at the transition gate, checks the user and the agent's role group, and runs it as the user. A Mutation runs from two clicks: `canvasAction` `kind=arm` gives nonces (16 random bytes, 30 seconds, one use, 5 a click, 10 a session), and `kind=mutation` needs one, the `activation` flag, a browser session and a Mutation name that the stored canvas lists (`crates/moqui-llm/src/assist/canvas.rs` `mutation`). The first click holds the evaluated write and answers its method, path, transition, parameters and hash (`ui::write::hold`), running nothing; the client shows the transition, the path and every parameter in a dialog (`js/WebrootAssist.js` `canvasAction`, `confirmCanvasWrite`), and the write runs only when the user's Save, with a new nonce, posts `confirm` equal to that hash, so a write the model or the values changed has another hash (plans/Security-Review.md SEC-AI-02, fixed). The confirm is the approval: an `AgentApproval` row records it and no card is shown. A value named like a secret is never stored or posted. Beside the label, a Button that runs a Mutation shows "saves:" and the last segment of the transition's path (`js/WebrootAssistCanvas.js` `savesText`). A Mutation the agent proposes with `write_ui` `run`, with no click, is an approval card like any other write. A Vue SFC component runs in `<iframe sandbox="allow-scripts">`. It talks to the page over a `MessageChannel` port handed over with a nonce. A submit from the frame opens a confirm drawn outside the frame, and the Save there is the first click; it posts through the same `canvasAction`, so the server's held write is confirmed in its dialog as well. While the user's preference `ASSIST_CANVAS_EXTERNAL` is on (the `x=1` of `GET /assist/sandbox`), a Vue SFC canvas reads nothing; the component's source and initial values are still the model's.

### Assistant text in the browser

The drawer renders an assistant text as Markdown with Marked (`escapeHtml: true`, so raw HTML is text), then DOMPurify, then a walk of the cleaned DOM (`js/WebrootAssist.js` `assist.sanitize`, then `v-html`). `style`, `form`, `input`, `button`, `iframe`, `object`, `embed`, `svg`, `math`, `video` and `audio` are forbidden tags. An image is replaced by a text placeholder that names its host, unless its `src` is a static image path of this site or `/richTextImage/<id>` (`siteImage`: a path with an image extension, no query or fragment, not under `/apps`, `/qapps`, `/rest`, `/assist`, `/vapps`, `/s1`, `/e1` or `/m1`, no `//`, no `..`, no white space or backslash; the canvas rule). Such an image stays, and the browser fetches it with the user's cookies (SEC-AI-03, fixed). A link keeps its `href` only when it is a site path or an `http(s)` URL. An external link is kept as the model wrote it and opens in a new tab with `noopener,noreferrer`; its title is the host the browser goes to (after any `user:password@`). One that carries data past its host and path (a query, a fragment, or a user and password; `assist.externalCarries`) shows its whole address as its title and opens only after the user OKs a dialog that names the whole URL and its host (`assist.confirmExternal`). A link the server marked as invented is shown as text. A canvas's Markdown is strict: no image and no external link.

### Untrusted text

`moqui_llm::prompt::untrusted` wraps text as `<untrusted from="...">` with its markers elided. It wraps: a remote A2A agent's card, question and answer; an MCP server's descriptions and results; a chat thread's earlier messages; a document trigger's records; an AI task's input; a text attachment's lines; a learned skill's text; a lesson; a conversation summary; a canvas problem's message; an inline text action's field text; the dev-aide `hosting` tool's answers. The results of the `screen`, `data` (lists and entities), `search` and service tools are not wrapped. For those the controls are the core prompt's rule that tool text is data (`framework/prompt/core.md`) and the approval of every write.

### Skills, memory and lessons

A skill is text the model loads with the `skill` tool; the server runs none of its steps. File skills come from a component's `skill/` directory; those of mr-boss are in [Attack-Surface-Apps-BOSS.md](Attack-Surface-Apps-BOSS.md#agent-skills). A user's own skill is personal: `skill` `op=save` stores it for that user, and saving one an agent drafted needs `AgentSkillAuthor` (`crates/moqui-llm/src/assist/extras.rs`). `op=share` makes a site copy in Draft, which only an admin publishes in System › LLM › Skills (`crates/moqui-llm/src/skills/learn.rs`). A learned skill's text reaches the model inside `<untrusted from="learned-skill">`. Memory holds facts for one user, 200 characters each. By the module comment of `crates/moqui-llm/src/tools/remember.rs`, the `remember` tool keeps a fact at once only on the drawer or the terminal with no tool output since the user's last message; otherwise it is a confirm card. A lesson is Proposed and active for its author only until `review#AgentLesson` approves it.

### Triggers

An `AgentTrigger` starts a run on the `job` surface as the trigger's `runAsUserId`, else the agent's. `org.moqui.agent.AgentTriggerServices.store#AgentTrigger` and `reset#AgentTriggerBreaker` need `AgentAdmin`. `fire#AgentTrigger`, `receive#TriggerDocuments` and `delete#TriggerDocument` are `authenticate="anonymous-all"` and check no permission in their bodies (`crates/moqui-llm/src/trigger.rs`). Their callers in this repository are the `ServiceJob` `agent_trigger_<triggerId>`, the `AgentTriggers` data feed, the scheduler's sweep, and the `fireTrigger` transition of System › LLM › Triggers (`AgentAdmin` on the screen). No rest-api file names an agent service ([how a service is reached](Attack-Surface-Web.md#services-and-allow-remote)). A firing is skipped while the trigger is paused, its breaker is open, or a limit is reached (defaults: 2 concurrent runs, 60 an hour). Three failures in a row open the breaker. A document trigger's changed records reach the model inside `<untrusted from="record">`, each cut to 1500 characters and 8000 in all. A record change the trigger's own agent made does not fire it.

### AI tasks and speech

`org.moqui.agent.AiTaskServices.run#Summarize`, `run#Classify`, `run#Extract`, `run#Translate`, `run#Generate` and `run#AiTask` run one completion for the current user. They need no `AgentUse`; `LlmFacade::complete` refuses an `EXTERNAL_USER` and checks the user's `api` quota. A task's input is at most 60,000 characters and is wrapped as untrusted. An async task may name a webhook in its `webhookUrl` parameter, so the service's caller chooses the address: `https` only, internal addresses refused at connect ([the guard](Attack-Surface-Outbound.md#the-internal-address-guard)), no redirect, 15 seconds. The POST carries the task's outcome and trace headers.

`org.moqui.call.SpeechServices.transcribe#Audio` is `authenticate="false"`. It reads the bytes at any `audioLocation` it is given and sends them to the model bound to `transcribe` ([Call captions](Attack-Surface-Comms.md#call-captions)). Its callers are the voicemail job, the Mantle voice note check and the drawer's `transcribe` call; each passes a stored location or the upload.

### Semantic find

`POST /find/rank` (webroot `find.xml`, `require-authentication="false"`, `track-artifact-hit="false"`) answers 401 without a signed-in user and checks no permission. It answers 503 on the default conf, which has no embedder (`search-facade` `semantic`). The body is JSON `{query, texts, limit}`, passed to `org.moqui.search.SearchServices.rank#Texts`. At most 5000 texts, each cut to 2000 characters, go to the embedding model in requests of 64 (`crates/moqui-core/src/search/rank.rs`, `crates/moqui-llm/src/embed.rs`). Every embedding call made for a user, this path's included, is refused for an `EXTERNAL_USER`, checked against the user's `api` quota and counted as an AT_LLM tarpit hit `embed:<modelId>` (`LlmFacade::embed_batches`; artifact group `LlmEmbedCalls`, 120 a minute); work with no user (the embedding worker, jobs) is not, and a call whose texts are all cached makes no check. Vectors are cached in memory (20,000). Each request to the model is an `LlmCall` of source `embed`.

### Model providers

Every model call is an outbound POST from the server to an endpoint's URL, with the endpoint's key and the model request (the prompt and the conversation) as its body. The default endpoint is `default`, protocol `chat-completions`, at `llm_openai_url` (`https://api.openai.com`). Its key is `llm_openai_api_key` (empty, `is-secret`). With an empty key no auth header is sent. The default model has no name until `llm_openai_model` is set, so no call goes out on the default conf. The other endpoints in `MoquiDefaultConf.xml` (xAI, Anthropic, Gemini, GLM, DeepSeek) are inside XML comments. An endpoint is configured in the conf or by an `LlmEndpoint` row, which overrides a conf endpoint by id; `store#moqui.llm.LlmEndpoint` runs from System › LLM › Models, which needs `AgentAdmin`. `LlmEndpoint.apiKey` is an encrypted field. A row that moves an endpoint to another origin without a key of its own drops the conf's key (`crates/moqui-llm/src/registry.rs`). An endpoint's key may also come from the property or environment variable its conf `api-key-env` names; no entity field sets that name. A provider call follows no redirect. The address check reads only an address written in the URL (`crates/moqui-llm/src/provider/mod.rs` `check_address`; the row in [Attack-Surface-Outbound.md](Attack-Surface-Outbound.md#requests-the-server-makes)): a private or link-local address needs `allow-private-network` or `local`, loopback is always allowed, and a host name is not resolved for the check. `org.moqui.agent.AgentAdminServices.test#Endpoint` and `probe#Model` (`AgentAdmin`) make a call to the endpoint and return the reply text or the error text.

### Remote agents and MCP servers

The MCP client is on (`mcp client-enabled="true"`). It calls only the servers of `AgentMcpServer` rows, and the A2A client only the remote agents of `AgentRemoteA2a` rows. `org.moqui.agent.RemoteAgentServices.store#AgentRemoteA2a`, `store#AgentMcpServer`, `store#AgentMcpServerTool`, `test#AgentRemoteA2a` and `test#AgentMcpServer` need `AgentAdmin`, so an `AgentAdmin` chooses each address. A row's URL is `https` unless `allowPrivateNetwork` is `Y` and the host is internal (`crates/moqui-llm/src/remote.rs` `check_url`). Every call is checked to be on the row's origin, goes through a client that refuses internal addresses at connect time unless the row allows them ([the guard](Attack-Surface-Outbound.md#the-internal-address-guard)), and follows no redirect. A call carries the question or the tool arguments the model wrote, the row's credentials and trace headers. `authJson` is an encrypted field and is never returned. With `perUserAuth` a call uses the user's `AgentMcpUserToken` row (`tokenJson`, encrypted); no service, screen or OAuth flow in this repository writes that entity. Remote tools are EXTERNAL, so a call asks for an approval, unless an admin marks an MCP tool otherwise. A call does not go out in a sim.

### Constitution services

The artifact group `ConstitutionServices` is granted `AUTHZT_ALWAYS`, `AUTHZA_ALL`, inheritable, to `ALL_USERS` (`AgentTypeData.xml`). It covers eleven services of `org.moqui.admin.ConstitutionServices`. Each checks in its body (`crates/moqui-llm/src/constitution/services.rs`). `store#Constitution`, `create#ConstitutionCustomization`, `reset#Constitution` and `store#ReferenceOrigins` need the sealed permission `ADMIN_CONSTITUTION_GLOBAL`, which the seed grants to `ADMIN`. The readers need a signed-in user; a run's snapshot is for the run's user or an `AgentAdmin`. `validate#Constitution` and `edit#ConstitutionDocument` write nothing. `record#ConstitutionChange` is not in the group. The webroot transitions `GET /assist/constitution` and `GET /assist/constitutionReference` call the readers for any signed-in user and remove `instructions` and `documentText` from the answer.

### System › LLM, the content log and audit

Every screen under `System/Llm` returns an error without `AgentAdmin` (`always-actions` of `Llm.xml`; the row in [Attack-Surface-Tools.md](Attack-Surface-Tools.md)). The Rust services behind them check `AgentAdmin` again, except the entity-auto ones (`store#moqui.llm.LlmEndpoint`, `LlmModel`, `LlmFeatureBinding`, `LlmModelAlias`, `store#moqui.agent.AgentToolPolicy`, `delete#moqui.agent.AgentToolExposure`) and the eval transitions. `org.moqui.agent.AgentAdminServices.rollup#LlmUsage` and `clean#LlmCallContent` are `authenticate="false"` and run only with authorization disabled (the jobs) or for an `AgentAdmin`; `clean#LlmCallContent` takes `retentionDays`. Their callers are the jobs and the `rollupUsage` transition of System › LLM › Usage. `org.moqui.agent.AgentServices.record#AgentRunUsage` loads a run by id where it has an `externalHarnessId`, writes steps and cost to it and can request its cancel, only with authorization disabled or for the run's own user (anyone else is told the run is not found). Only its definition in `AgentServices.xml` names it: no screen, rest-api file or other code in this repository calls it.

`LlmCall.requestJson` and `responseJson` are kept only when `llm_log_content` is true (default false), redacted by key name and token shape, not encrypted, and cleared after `retention-days` (14) by the job `clean_LlmCallContent_daily`. Conversations, messages, tool arguments and results, and run events are stored always, unencrypted. `get#LlmCallContent` and `get#AgentAuditView` show content to its own user, or to a user with `AgentAudit`, and write an `AgentAuditLog` row for each such read. `AgentAdmin` alone gets metadata. The four list screens (calls, conversations, runs, approvals) select metadata fields only; the content fields are plain columns of the same entities.

### External agent bridge

`moqui_core::service::external_agent::request` starts the program that `MOQUI_EXTERNAL_AGENT_COMMAND` names; its row is in [Attack-Surface-Process.md](Attack-Surface-Process.md#child-processes). The child gets a named environment (`moqui_lib::env::limit_child_env`: `PATH`, `HOME`, the locale and the like, plus the names `MOQUI_EXTERNAL_AGENT_ENV` lists), never the server's (SEC-AI-12, fixed), and the server's working directory. The function reads no user and checks no permission. No service definition in this repository names that location, so nothing calls it until a component defines one.

No screen uses it; it is the "may run scripts" grant that an ETL mapping's `expression` fields need ([Database](../tools/Database.md#etl)).
