# Attack surface: routes, screens and REST

The host routes and servlets, the root screen tree and its public paths, token routes, and REST. A row for another area (telemetry, XMPP, git, DAV, the LLM routes) stays in the host table here and links to that area's file. This is one file of the attack surface map. The index, how to read a row, the defaults and the lock-down advice are in [Attack-Surface.md](Attack-Surface.md).

`search_backend` defaults to `postgres`, so both proxies answer 404 on a default install after authentication. Each proxy's `max-body` is `100m`. Hop-by-hop headers are stripped, and so are `host`, `authorization`, `cookie`, and `content-length`. The client's `Authorization` and cookies are not forwarded. Upstream Basic is the servlet's user and password init-params (`elasticsearch_user` / `elasticsearch_password` for search; the dashboard init-params for Kibana). The proxy timeout is 120 seconds. HTTP request spans are recorded by the factory-scoped telemetry middleware.

A `<public-site>` may name a `host-check-service`, called with the site, host and path for a request to a framework route (the `FRAMEWORK_ROUTES` of `screen/public_site.rs`: `/apps`, `/qapps`, `/rest`, `/Login`, `/sso`, the token routes, the servlets, `/status`...) on its host. When it answers `restricted` true the route is 404 there, before any servlet, token route, screen or `before-request` action runs, so nobody signs in to the framework or reaches its apps on that host (a site's theme preview host, Commerce F87; mr-pass points it at Mantle's `get#PreviewHost`). A path another servlet takes (`/fop`, `/search`, `/dashboard`, an app's own) is refused the same way, and the refusal makes no session. The static routes a page there loads (`/js`, `/css`, `/libs`, `/images`, `/static`, `/assets`) are not checked while the screen path stays under them: `/libs/../apps` is the apps, and is checked. A check that fails refuses the route and is logged. The host routes above (`/health`, `/metrics`, `/notws`, `/termws` and the others) are answered before this check: the probes keep their IP list, and the sockets need a session cookie, which a host where nobody can sign in never issues.

Root screens by host name ([Run-Deploy](../Run-Deploy.md#several-sites-by-host-name), plans/Edge-Node2.md §4.2): a `root-screen` whose host pattern matches the `Host` header (its port left off, lower case) gives that host its own root screen; any other host gets the `.*` root, `webroot.xml`. A host is not trusted by being sent: an unknown one is the default root's. With `framework-routes="refuse"` the host serves its root's screens and the shared static files only: the token routes and the servlets are 404 there before they run, as on a public site's restricted host but with no service call, and so are the host routes above (`/health`, `/metrics`, the sockets, `/dav`, the LLM and channel routes), by a layer on them, and the gRPC services of the HTTPS listener (the OTLP receiver, the PASS authority), whose calls go to the router instead. Left to such a host, each behind its own authentication and web protection: git over HTTP and Git LFS under `/git/` (git at a public site's page URL too, when it is also a `public-site` host, served at its `/git/` path) and the CI runner REST under `/ci/runner/` (`moqui_core::web::reserved::SERVED_ON_REFUSING_HOSTS`), so a site's own host can be its clone and runner URL. The first path segments the framework reserves on every host are one list, `moqui_core::web::reserved` (`ec.web.reservedPaths` to scripts, which adds the first segment of each servlet the conf declares, enabled or not: `/search`, `/dashboard`, PASS's `/trk` and `/trk-o`): a public site's routes never take one, git at a page's URL never starts with one, and a test fails for a host route that is not under it. `.well-known` and `ci` are reserved for pages only under the host's own sub-paths (`ec.web.reservedSubPaths`: `ci/runner`, `.well-known/caldav`, `carddav`, `agent-card.json`, `mcp.json`, `ai-catalog.json`), so a site serves its own `/.well-known/security.txt` or a page at `/ci`; a public site's route is checked by the path as written and as the screens resolve it (`..`). As a name that owns everything under it (a repository group, a mount, git at a page's URL) each stays reserved whole. The gRPC listener on its own port (`grpc-port`, `pass_authority_grpc_port`) is not by host and is not affected. A `root-screen` conf that cannot be read (an invalid host pattern) refuses the framework's routes on every host. With `include` the host gets `webroot.xml`'s screens and routes beside its own. A link made in a request (`ec.web.getWebappRootUrl`) uses the request's host only when the whole `Host` header is a plain host name (letters, digits, `-` and `.`) with at most a numeric port, a `root-screen` pattern other than `.*` names it and that root does not refuse the framework's routes; the one normalized value is checked and written, with the conf's scheme and port. Else the conf's `webapp_http_host`, as always outside a request. A public site whose root is also its host's root screen is still routed and bound by its `public-site`, and a request that no public-site route takes has no bound site: a `resolvedSiteId` parameter it sends is dropped.

There is no axum route for `/groovysh`, `/rpc`, `/elastic`, `/kibana`, `/htmlr`, `/vapps`, or `/h2`. `/fop`, `/search`, and `/dashboard` are servlet patterns on the fallback. `/status` is a screen transition. The conf has no `/groovysh` endpoint, and the obsolete Groovy Shell screen has been removed. The browser's Terminal UI runs the applications; the privileged SSH admin shell provides the JavaScript executor ([SSH and the TUI](Attack-Surface-SSH.md#ssh-and-the-tui)).

## Screen tree

The root screen `component://webroot/screen/webroot.xml` sets `require-authentication="false"` so subscreens decide. The default subscreen item is `qapps`. There is no `vapps` item. Schema documents are the REST transitions, which require a user and `REST_SCHEMA`.

Because the root screen does not require a user, static files served as that screen's content are reachable without a login. The shell references `/js` and `/libs`, and the root names `/favicon.ico`. A full listing of those files was not made.

`qapps` is `require-authentication="false"` with extra path allowed, and its pre-actions redirect to `/Login` when there is no `userId`. The Assist drawer flag is `ec.llm.isEnabled()` and `hasPermission('AgentUse')`. `terminalUrl` is `/qapps/Terminal` only when `webapp_terminal_endpoint` is set.

### Token routes

Token routes are not framework-default paths. `runtime/components/addon/mr-boss/MoquiConf.xml` adds them on the `webroot` webapp, and `runtime/components/base/basic-comms/MoquiConf.xml` adds `call`. `screen/mod.rs` sends a match to token-route dispatch before the ordinary screen. The failure status of a bad token was not read.

| `u` | `/u/<token>` | `mantle.party.ConsentServices.check#UnsubscribeToken` | `Unsubscribe.xml`, post-transition `oneClick` |
| `cal` | `/cal/<token>` | `ironstone.commons.CalendarServices.check#PublishedCalendarToken` | `PublishedCalendar.xml` |

mr-boss also adds per-client rate limits: `request-form` on `POST /r/*/submit`, 5 requests in 60 seconds, burst 5; and
`invitation-accept` on `POST /i/*/*` (an invitation's account and factor steps), 10 requests in 60 seconds, burst 5.
They apply when per-client web protection is on.

A route's token is its credential, so it is kept out of what the server records. The request log (each request's SERVER
span) has `/i/:token/...` for `url.path`, and for a path or URL under a token route in the `Referer` header and in a
query value such as a sign-in step's `returnTo` (`screen::token_route::redact_url`). The log lines that name a request
path (a refused origin, the public-site host check) are redacted the same way, and so are a Visit's `initialRequest`
and `initialReferrer`. Browser telemetry (`/rum/traces`, `/rum/logs`, `/rum/replay`) has every string redacted before
it is stored, a replay's `url` and the links its rrweb snapshot holds included (`token_route::redact_json`). The routes
are read per conf generation, so a route a conf reload adds is redacted from then on. The route name and the rest of
the path stay (`/u/:token/oneClick`). `http.route` is the screen's location, which holds no token. The session keeps a
sign-in step's `returnTo` with its token (it is where the user goes next); a session is not a record.

While a token route's screen renders it is the root of its links (`web::set_link_prefix`): a form's action, a link and a
transition's redirect to a screen go to `/<name>/<token>/...`, not to `/<transition>` outside the route. A plain URL
(`/Login`) is not prefixed, and no request parameter or header sets the prefix: only the token route's dispatch does,
after its token check. A server-static qvt template is cached for every visitor, so it is made with no prefix
(`screen::statics::serve_template`) and its paths, an alias transition's target included, are still from the screen; a
token route's screen that needs links under the route should not be server-static. A `screen-last` path the session
saves (the page before a login) is from the screen as well.
