# The clients against OWASP MASVS

The desktop and mobile apps' standing against the OWASP Mobile Application Security Verification Standard (MASVS)
v2.1.0, control by control. The apps are `crates/moqui-mobile` (Android, Tauri on the platform's WebView) and
`crates/moqui-desktop` (Tauri on CEF, with its node and client modes), with the client both share
(`crates/moqui-client`, `crates/moqui-client-tauri`). The server's own matrix is the [ASVS matrix](../README.md); the
plan is [Proofs-Initial](../../../../plans/Proofs-Initial.md), phase P8.

Status 2026-11-19: one reading of the code at mr-moqui `a73f06673`, by four readers, one MASVS group pair each; no proof is
filed under it yet beyond the tests the Proof column names. The controls are MASVS's
([mas.owasp.org/MASVS](https://mas.owasp.org/MASVS/), © The OWASP Foundation, CC BY-SA 4.0, cited by id and not
copied); the weaknesses each row weighed are OWASP MASWE's ([mas.owasp.org/MASWE](https://mas.owasp.org/MASWE/)), by
their current ids. Each row's topic is in our words.

## Scope

- **Profiles.** MASVS 2.x has no levels of its own; they are the MAS testing profiles of its weaknesses. The owner's
  decision: L1, L2 and P (privacy) are covered. R (resilience against reverse engineering: tampering, root and
  debugger detection, obfuscation) is N/A by decision, as the apps are open source and CC0; every RESILIENCE weakness
  is of profile R only, so the four RESILIENCE controls are N/A.
- **The two apps.** The mobile app is held to MASVS as written; the desktop app by analogy, and where a control has
  no meaning on a desktop, the row says so.
