## Conventions

- **Lifecycle.** A document starts in `proposals/` when it has no code (and gets a paragraph in Future-Plans), moves to the root when it is active or next (its first paragraph is a dated status line), and goes to `archive/` when it is built, resolved or superseded. Archiving does not delete anything: the design or review stays whole as the record of what was decided and compared. What is left goes to Remaining-Work when it is for v0.1.0, else to Future-Plans; testing still needed goes to Testing-Needed.
- **Archiving a document.** `git mv` it; add `> Archived <date>: ...` under the title saying its state and where the live part went; grep the repository for its path (Markdown links, plain `plans/...` text, and `//!` doc comments under `crates/`) and fix each; move anything still open into Remaining-Work (for v0.1.0) or Future-Plans (after it), and checks not yet run into Testing-Needed, with a link back; move a parity review's accepted differences into Parity-Diffs and leave a pointer in the review; update this README.
- **Summaries.** Remaining-Work is the one list of open work for the first release, and Testing-Needed of open testing (live and platform checks, and tests to write); Future-Plans holds the open items for after v0.1.0 (an archived plan's next steps move there) and digests the proposals; Performance-Summary digests the performance set. A summary links to the detail and does not restate it.
- **Reviews going forward.** Name a parity review `<Area>-Parity-Review.md` and any other `<Area>-Review.md`. Keep the shape of the entity and service review: a summary with counts, a phase table per area with `ID | Rust location | Java location | Divergence | Severity | Intentional?`, a `####` section per open finding, a "checked and found equivalent" list, and an `## Accepted differences` table that moves to Parity-Diffs at archive time with its IDs.
- **UI reviews.** Use `ui-review-<area>.md`: scope/sources, method, screen/surface inventory, end-to-end activities,
  verification, coverage/findings/batch record and decisions. The inventory maps every surface to an activity;
