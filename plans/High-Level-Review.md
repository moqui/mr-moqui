#### HL-001. Index child matching during DataDocument assembly

**High · Supported by source.** A feed rebuild pages by primary key and queries a joined view for each page. Page size limits primary records, while related rows can still multiply within a page. For each joined row, assembly linearly searches each type-many child list using the child's direct projected fields. One parent with N distinct children can take O(N²) child comparisons, and sibling to-many joins can further multiply input rows. The same assembler serves document export and delivery by ID. Start with an assembly-local index for each parent and relationship keyed by the existing field equality, retaining insertion order, missing/null equivalence, and the current treatment of expression fields. Keep the SQL shape initially. Compare joined rows, comparisons, assembly time and peak memory for one large child list and for two sibling lists before considering separate relation fetches. [Feed rebuild](../crates/moqui-core/src/search/feed.rs#L575), [document paging and view query](../crates/moqui-entity/src/entity/document.rs#L405), [child merge](../crates/moqui-entity/src/entity/document.rs#L995).

#### HL-002. Batch entity cache invalidation at frame end

**High · Needs measurement.** A write sweeps its entity's cached lists. For updates and deletes it can scan the rows in each list for the primary key. Frame end can repeat that sweep per retained write until the existing threshold switches to a whole-cache clear. The cost can grow with both writes per frame and cached query variants, even when few cached lists contain the written rows. Compare the current strategy with a single sweep per entity that reuses a set of changed keys, or with an earlier whole-cache clear when selective eviction costs more than warming the cache. Preserve immediate invalidation, the frame-end pass for intervening readers, and conservative matching for incomplete values and views. Measure write and commit latency, entries and rows inspected, and subsequent cache miss rates in a mixed workload. This is distinct from Profiling's existing cached-read lock work. [Write hooks](../crates/moqui-entity/src/entity/cache.rs#L1002), [frame replay](../crates/moqui-entity/src/entity/cache.rs#L622), [eviction and matching](../crates/moqui-entity/src/entity/cache.rs#L677), [cache removal](../crates/moqui-lib/src/cache.rs#L449).

#### HL-003. Make bounded iteration an explicit driver capability

**Medium · Needs measurement.** Entity iteration opens the same driver stream API across targets. PostgreSQL fetches through a cursor and MySQL reads from an active result. Browser SQLite gathers all matching rows before returning the first one, so an early stop still pays for the entire result. First measure an uncached browser export or iterator consumer over growing data sets, including a consumer that reads only the first few rows. Compare time to first row and peak worker memory. If material, expose or document the buffering distinction and evaluate bounded SQLite iteration that preserves the statement lifetime, ordering and snapshot contract. The cached and sim-view paths intentionally use memory as well. [Entity iterator](../crates/moqui-entity/src/entity/find.rs#L553), [PostgreSQL cursor](../crates/moqui-drivers/src/postgres.rs#L640), [MySQL stream](../crates/moqui-drivers/src/mysql.rs#L391), [browser SQLite stream](../crates/moqui-browser/src/sqlite.rs#L208).

#### HL-006. Give async request adapters one completion path

**High · Supported by source.** The common host worker adapter and the notification socket adapter each start a Tokio blocking task that waits on a synchronous reply from a framework worker. The blocking task is occupied for queue wait plus execution. The bounded framework queue is reached only once that task runs. Screen HTTP, DAV, and MCP instead allocate an async oneshot inside each handler and pass a separate synchronous result through the same pool. Screen HTTP has queue-age, abandonment and overload handling that the simpler adapters do not share. Expose a completion hook at the pool boundary and use it from one host async adapter. Keep job context setup and completion after cleanup in the synchronous pool. Preserve each protocol's deadlines, auth-failure accounting, and treatment of started writes when a caller disconnects. Start with the two waiting adapters, then migrate HTTP adapters when their policies can be expressed explicitly. Under mixed HTTP and protocol traffic, compare blocking threads occupied, queue wait, overload response and shutdown completion. [Pool admission and completion](../crates/moqui-core/src/service/request_pool.rs#L101), [common worker adapter](../crates/moqui-host/src/worker.rs#L23), [notification worker adapter](../crates/moqui-host/src/notws.rs#L576), [screen HTTP admission](../crates/moqui-host/src/http.rs#L898), [DAV adapter](../crates/moqui-host/src/dav_http.rs#L83), [MCP adapter](../crates/moqui-host/src/llm/mcp.rs#L88).

#### HL-008. Isolate SFU packet work to the peers it affects

**High · Supported by source.** A UDP or TCP media packet reaches `Sfu::handle_receive`, which searches peers on the whole media node for an RTC session that accepts it. Each accepted packet then calls `drive`, which polls every peer and scans for dead peers on each propagation pass, even across unrelated rooms. This adds O(P) node-wide work per accepted packet for P peers before necessary room fan-out. First instrument peer polls and accept checks with increasing numbers of independent rooms at fixed per-room traffic. Use CPU per packet, output latency and packet loss to size the work. If the poll cost dominates, drive peers with pending work and track their deadlines. Treat transport demultiplexing as a separate change and keep RTC's acceptance check authoritative during ICE migration and relay changes. Preserve per-peer ordering, timers, and generation fences. [Host media driver](../crates/moqui-host/src/rtc/driver.rs#L133), [SFU receive and timeout](../crates/moqui-rtc/src/sfu/mod.rs#L752), [all-peer drive](../crates/moqui-rtc/src/sfu/mod.rs#L899), [room fan-out](../crates/moqui-rtc/src/sfu/mod.rs#L930).

#### HL-009. Route targeted pushes through user indexes

**Medium · Supported by source.** Notification WebSocket fan-out snapshots all S sockets and linearly tests the recipient list of size U for each one, O(S × U) in the worst case. XMPP uses a recipient set and still scans every registered session. Both have user-specific presence or lookup operations that also scan. Start with a user-to-connection index in the WebSocket registry and retain the ID lookup for direct call signaling. Apply the same indexing approach to XMPP if warranted, keeping topic filtering, per-session queues, overflow closure and stream resumption with their existing owners. Measure registry work and enqueue latency with many idle connections and small recipient lists, then with a large broadcast. [WebSocket fan-out](../crates/moqui-host/src/notws.rs#L597), [direct and presence lookup](../crates/moqui-host/src/notws.rs#L530), [XMPP registry](../crates/moqui-xmpp/src/registry.rs#L82).

#### HL-010. Put drive file service calls behind one adapter

**Medium · Supported by source.** WebDAV and the SFTP-facing tree already share drive lookup and some metadata helpers. Both still call the same resource-info service, open storage under a scoped authorization bypass after the access check, and translate uploads through the same upload service and result shape. Extract the authorized open and upload operations into the existing drive adapter. Keep WebDAV lock tokens, conditional requests, range responses and SFTP handle semantics in their callers. A shared open operation gives a later range or streaming change a common place to use a byte source, since WebDAV currently reads the whole file before slicing a range. Verify access denial and version creation on both paths before changing transfer behavior. #### HL-011. Bound mailbox import by a message window

**Medium · Supported by source.** Import reads a resource as a byte vector, collects an mbox into separate message buffers, and loads every existing message ID in the destination folder before processing any new messages. Working memory grows with archive bytes and existing folder size, even for a small import into a large folder. Start by iterating the mbox parser over the source without collecting messages. Then use a reader where the resource supports it and check IDs in bounded batches, retaining duplicate handling within the import and independent per-message commits. Measure peak resident memory, time to first stored message and database queries as archive size and pre-existing folder size vary independently. #### HL-012. Aggregate LLM quota reads at admission

**High · Supported by source.** Agent steps, the gateway and API callers use the same quota path. For each applicable limit it loads today's call rows and sums them in Rust. A daily and monthly limit with the same source scope repeat that read within one check. Repeated admissions for a busy account can revisit earlier calls throughout the day. Compute today's usage once per distinct scope in the check and push token and cost aggregation down to the database if the totals can be kept equivalent. Preserve timezone boundaries, decimal and null behavior, source filtering, monthly rollups and visibility of current calls. Check rows transferred, admission latency and DB CPU at low and high calls per user per day. Only consider write-side counters if aggregate queries remain a bottleneck. [Call totals](../crates/moqui-llm/src/usage.rs#L787), [quota loop](../crates/moqui-llm/src/usage.rs#L870), [agent step check](../crates/moqui-llm/src/run/step.rs#L1069), [gateway check](../crates/moqui-llm/src/gateway.rs#L1088).

#### HL-013. Read only active history when building model requests

**Medium · Supported by source.** Every model step loads all message rows in the conversation. It excludes compacted messages in Rust and already limits the part query to the remaining IDs. Compaction bounds what the model sees but the message rows read can still grow with lifetime conversation length at a fixed active window. Move the compacted-row exclusion to the message query, retaining null and false semantics, sequence order, the saved summary and the newest assistant estimate anchor. Keep full history available to display and audit callers. Compare message rows read and prompt-build latency with the same active window at different lifetime lengths. Keep the frozen prefix and provider replay behavior stable. [Step request assembly](../crates/moqui-llm/src/run/step.rs#L1176), [history loader](../crates/moqui-llm/src/window.rs#L882).
